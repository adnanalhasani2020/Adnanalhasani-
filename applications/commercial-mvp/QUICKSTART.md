# تشغيل النسخة التجارية الأولى محلياً

## المتطلبات
- Python 3.11 أو أحدث.
- قاعدة SQLite قابلة للكتابة.
- يجب إعداد بيانات النشاط والمنتجات والعروض ومراكز المخزون الفعلية والسعر الفعال قبل أن يظهر أي منتج في الكتالوج.

## التشغيل
من جذر المستودع:

```bash
PYTHONPATH=src python -m agent_core.commercial_web
```

افتح `http://127.0.0.1:8080`. في أول تشغيل تُطبّق ترحيلات قاعدة البيانات تلقائياً على `commercial-mvp.sqlite3`. يمكن تغيير المسار عبر `COMMERCIAL_DB_PATH`، والمنفذ عبر `COMMERCIAL_PORT`.

## ما يتضمنه المسار
- تسجيل حساب باسم مستخدم وكلمة مرور (تخزين scrypt salt/hash، لا كلمة المرور الخام).
- جلسة عشوائية محدودة بثماني ساعات؛ يخزن النظام hash للرمز فقط، ويستخدم Cookie من نوع HttpOnly وSameSite=Lax.
- كتالوج لا يعرض إلا العروض النشطة التي لها سعر واحد فعّال وكمية مخزون معروفة وغير ملتبسة وموجبة ضمن نفس العرض والنشاط والنطاق والموقع.
- عملية شراء ذرية: تحقق المخزون والسعر، إنشاء Sale وانتقاله عبر التفويضات المطلوبة، تثبيت سطر البيع والسعر، حركة مخزون غير قابلة للتعديل، وإيصال إعادة الطلب في معاملة واحدة.
- نفس مفتاح الإعادة والحمولة يعيد الإيصال السابق؛ إعادة استخدام المفتاح مع حمولة مختلفة تُرفض.

## إعداد البيانات
هذه الواجهة لا تنشئ مخزوناً أو سعراً افتراضياً ولا تعرض بيانات تجريبية. يلزم أن تكون بيانات Product وOffering وActivity وInventoryPosition موجودة فعلياً، وأن يكون للعرض سجل `offering_prices` فعال بالعملة `SAR` أو `YER` أو `USD`. لا يظهر العرض إذا كانت الكمية مجهولة أو صفرية أو ملتبسة أو إذا لم يوجد سعر فعّال واحد.

## حدود مهمة قبل النشر العام
- الخادم مربوط افتراضياً بـ`127.0.0.1` ولا يفعّل HTTPS بنفسه. لا تربطه بالإنترنت مباشرة؛ استخدم reverse proxy مع TLS واضبط `COMMERCIAL_COOKIE_SECURE=1`.
- هذا إصدار أولي بلا بوابة دفع إلكتروني؛ إيصال البيع لا يثبت أن المال انتقل.
- لا توجد حتى الآن واجهة إدارة لإنشاء المنتجات والأسعار ومخزون البداية؛ استخدم تطبيقات المجال الحالية وإجراءات المخزون المعتمدة لتجهيز البيانات.
- سياسة الإرجاع ورد المخزون، التسويات، الضرائب، الخصومات، والفواتير النهائية خارج هذا المسار.
- لا تدمج طلب التغيير قبل نجاح اختبارات CI على آخر commit ومراجعة مسار التفويض والجلسات.
