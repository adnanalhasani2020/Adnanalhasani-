# العلاقات المالية User ↔ User

## النتائج
- loan أضيق من debt: القرض يصف علاقة تمويل/إقراض؛ debt يصف التزاماً مالياً مستحقاً.
- obligation أوسع ويمكن أن يكون غير مالي.
- payment فعل وفاء/نقل قيمة؛ settlement عملية إتمام أو حسم الالتزام؛ transfer يصف حركة قيمة ولا يثبت وحده سببها.
- receivable حق مالي متوقع/مستحق لطرف، payable التزام لطرف آخر.
- هذه المصطلحات لا تجعل النظام بنكاً أو مقرضاً تلقائياً.

## قرار نطاق
Q-0028 يظل قراراً بشرياً: هل النظام مجرد سجل/تنظيم علاقة، أم يصبح طرفاً أو حاملاً للقيمة أو منفذاً للالتزام؟
