# EXEC-0018 — Durable operation identity binding

## Gap
The durable operation registry keyed records by `namespace + operation_id` and compared duplicate request fingerprints, but a retry with the same fingerprint could supply a different `operation_kind` or `actor_context_ref`. Returning the existing record in that case concealed a metadata rebinding attempt.

## Implemented behavior
- A duplicate key remains idempotent only when the request fingerprint, operation kind, and actor-context reference match the original reservation.
- Mismatched fingerprint, operation kind, or actor context fails closed with a validation error.
- The registry remains an identity/idempotency boundary only. It does not execute domain effects, resolve conflicts, or declare domain finality.

## Tests
`tests/test_stage32_durable_operation_application.py` covers operation-kind and actor-context rebinding attempts, asserting the original durable record remains unchanged and unique.

No new authorization model, offline finality, domain state mutation, payment, settlement, or financial effect is introduced.
