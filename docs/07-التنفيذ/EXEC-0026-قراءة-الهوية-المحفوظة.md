# EXEC-0026 — Persisted identity read application path

## Evidence of gap
The relational schema already persists `persons` and `identifiers`, while `domain_identity.py` defines in-memory domain values and `IdentityApplication` in `application.py` creates those values in memory. This change adds a read-only application path over existing persisted identity records without creating a second identity model.

## Capability
- Read a Person by UUID, restoring its persisted state, canonical-person reference, timestamps, and version.
- List identifiers belonging to one Person, with deterministic ordering by creation timestamp and identifier ID.
- Return `None` for an absent Person and an empty tuple when a valid UUID has no persisted identifiers.
- Reject malformed UUID inputs.
- Keep queries scoped to the requested Person.

## Boundary
Read-only. No Person creation, merge/correction, identifier issuance/revocation, uniqueness policy, authentication, account access, or authorization is introduced. The reader does not infer whether an identifier is verified or suitable for login.

## Implementation and tests
- Implementation: `src/agent_core/identity_read.py`
- Tests: `tests/test_stage39_identity_read_application.py`
- Coverage: persisted field restoration, missing record, person-scoped identifier listing, deterministic order, empty result, and malformed UUID rejection.

## Traceability
