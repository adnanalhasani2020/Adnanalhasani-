# EXEC-0031 — Persisted Access Account read path

## Evidence of gap
The relational schema persists Access Account records, but the existing application surface does not provide a dedicated read path to restore them by identifier or list them for a Person. This delivery uses the existing schema without a migration.

## Capability
- Restore one persisted Access Account by UUID.
- List a Person's Access Accounts in deterministic creation-time and ID order.
- Return `None` for an absent account and an empty tuple for a valid Person UUID with no persisted accounts.
- Reject malformed UUID inputs.

## Boundary
Read-only. This service does not create or mutate accounts, authenticate a person, enroll authenticators, create sessions, grant authorization, or infer whether an account state permits access. Existing persisted state is reported as stored.

## Implementation and tests
- Implementation: `src/agent_core/access_account_read.py`
- Tests: `tests/test_stage43_access_account_read.py`
- Coverage: persistence/reopen, stored state restoration, missing records, Person scoping, deterministic ordering, and malformed UUID rejection.

## Traceability
Identity / Access Account persistence → `PersistedAccessAccountReader` → `tests/test_stage43_access_account_read.py`.
