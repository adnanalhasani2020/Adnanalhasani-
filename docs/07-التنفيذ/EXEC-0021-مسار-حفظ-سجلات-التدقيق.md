# EXEC-0021 — Persisted Audit Record append path

## Evidence of gap
- `domain_audit.py` defined AuditRecord and Provenance as in-memory values.
- The existing relational schema already defines `audit_records` with explicit event type, actor context, target, occurrence time, result status, operation/correlation references, provenance reference, and creation time.
- No application path was found that appends an explicitly supplied audit record into that table.

## Implemented capability
- Append an audit record with caller-supplied event type, actor-context reference, target, result status, and timezone-aware timestamps.
- Preserve optional operation, correlation, and provenance references without inventing values.
- Return the immutable persisted-record representation after the write.

## Boundary
- This is an explicit append operation, not automatic auditing of all domain mutations.
- It does not infer actor identity, authorization, event taxonomies, retention policy, or atomicity with domain writes performed by another service.
- It does not treat Audit as Domain History or a source of domain truth.
- No schema migration or new read interface is introduced.

## Tests
`tests/test_stage36_audit_record_persistence.py` covers persisted fields after database reopen, required core fields, and timezone-aware timestamp validation.
