# EXEC-0022 — Persisted Provenance Record application path

## Evidence of gap
- The existing relational schema defines `provenance_records` with source type/reference, optional source version and as-of time, derivation type, and creation time.
- The existing `Provenance` domain value is in-memory; no application path was found to append, restore, or list provenance records from that table.

## Implemented capability
- Append explicitly supplied provenance records to the existing table.
- Validate required source/derivation references, UUIDs, and timezone-aware timestamps.
- Restore a record by ID and list records for an exact source type/reference in deterministic order.

## Boundary
- No source lineage, derivation semantics, actor identity, or missing fields are inferred.
- No automatic provenance attachment to domain writes or cross-service transaction atomicity is introduced.
- Provenance records do not replace Audit or Domain History, and this work adds no schema migration.

## Tests
`tests/test_stage37_provenance_record_persistence.py` covers persistence across database reopen, retrieval/listing, required-field validation, UUID validation, and timezone-aware as-of validation.
