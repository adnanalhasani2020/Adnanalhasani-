## 1. الهدف
تحويل ما ثبت في REQ/Architecture/Data Model/SPEC إلى تنفيذ قابل للتتبع والاستبدال والمراجعة والاختبار، مع إبقاء القرارات المفتوحة خارج التنفيذ المتأثر بها.

Stage 7 لا تعني بناء التطبيق كاملاً في دفعة واحدة، ولا تعني اختيار تقنية نهائية مسبقاً.

## 2. ما أصبح ثابتاً وقابلاً للتنفيذ
- حدود المجالات وملكية Source of Truth.
- الفصل بين Person / Access Account / Financial Account.
- Activity / Organization / Membership / Role Assignment، مع فصلها عن Authorization.
- Product / Offering / Sale، مع بقاء Inventory وAvailability بمالكيهما.
- Financial Account / Ledger / Balance كحدود Finance، مع فصل Payment وSettlement.
- Patient Context / Encounter / Clinical Record / Result / Prescription كحقيقة Health، مع عدم جعل Agent صاحب القرار السريري.
- Family Relationship / Delegation / Authorization كحدود منفصلة.
- Conversation / Message كحقيقة Communication دون امتلاك Health/Finance truth.
- Agent / Authority Policy / Agent Action / Approval / Provenance / Audit كحدود دلالية منفصلة.
- Offline / Pending Operation / Device / Conflict كحالات تشغيلية لا تنشئ Finality أو Source of Truth.
- History / Provenance / Audit وقواعد عدم حذف التاريخ المفاهيمي.
- Traceability REQ → SPEC وPrimary/Supporting ownership.

## 3. القرارات التي كانت Decision-Dependent وأصبحت الآن محسومة
- DEC-0001: الولاية/السوق؛ يمنع تثبيت قواعد قانونية أو قطاعية عامة.
- DEC-0002: معنى Primary Account؛ يمنع تثبيت تجميع/حساب رئيسي غير محسوم.
- DEC-0003: دور النظام في العلاقات المالية؛ يمنع افتراض أن النظام مقرض/طرف مالي قانوني.
- DEC-0004: نموذج الأسرة والتفويض؛ يمنع افتراض أهلية/وصاية أو صلاحيات أسرية عامة.
- DEC-0005: أنواع السندات والقسائم؛ يمنع تثبيت الأثر المالي لنوع Instrument غير محسوم.
- DEC-0006: حدود الوكيل المالية؛ يمنع أفعالاً مالية ذات سلطة غير محسومة.
- DEC-0007: حدود الوكيل الصحية؛ يمنع استقلالية سريرية أو أفعالاً صحية غير محسومة.
- DEC-0008: القنوات التجارية المدعومة؛ يمنع قفل قائمة قنوات تجارية نهائية.
- DEC-0009: معنى «متاح قريباً»؛ يمنع تثبيت خوارزمية/تعريف قرب نهائي.
- DEC-0010: أولوية/نطاق الصحة والتعليم؛ يمنع ترتيب نطاق مرحلي نهائي.
- DEC-0011: سياسة Offline المالية؛ يمنع Finality أو قبول أعمال مالية Offline غير محسومة.
- DEC-0012: مصدر الحسم عند اختلاف المخزون/الأجهزة؛ يمنع اختيار قاعدة تعارض نهائية.
- DEC-0013: أثر فقدان الجهاز والعمليات المعلقة؛ يمنع سياسة استعادة/فقد نهائية.

## 4. قاعدة التنفيذ بعد حسم القرار
حسم القرار لا يعني أن التنفيذ قد اكتمل. يُنفذ أثره فقط عبر REQ/SPEC/EXEC المعتمدة، مع إبقاء التفاصيل المؤجلة أو غير المحسومة خلف حدود قابلة للتغيير. لا يجوز تحويل اختيار تقني إلى قرار جديد ضمنياً.

## 5. سلسلة التتبع
REQ → SPEC → EXEC → Implementation → REVIEW → TEST → ACHIEVEMENT

كل EXEC يجب أن تسجل REQs وSPECs التي تغطيها، وما إذا كانت قابلة للتنفيذ الآن أو مشروطة بـDEC/Research.

## 6. ترتيب التنفيذ المقترح
1. EXEC-0001 — Project/Repository foundation + runtime structure.
2. EXEC-0002 — Identity / Person / Identifier / Access Account / Session foundations.
3. EXEC-0003 — Activity / Organization / Membership / Role Assignment foundations.
4. EXEC-0011 — Inventory / Discovery foundations.
5. EXEC-0004 — Product / Offering / Sale foundations.
6. EXEC-0005 — Financial core foundations، مع عزل الأجزاء Decision-Dependent.
7. EXEC-0006 — Health core foundations، دون افتراضات تنظيمية أو استقلالية AI.
8. EXEC-0012 — Education context foundations، مع إبقاء نطاق الأولوية مؤجلاً.
9. EXEC-0007 — Family / Delegation / Authorization.
10. EXEC-0008 — Communication.
11. EXEC-0009 — Agent / Approval / Provenance / Audit.
12. EXEC-0010 — Offline / Pending / Device / Conflict foundations.
13. EXEC-0013 — Cross-domain exceptions / correction / acceptance hardening.

هذا ترتيب تنفيذي مبدئي، وليس التزاماً بترتيب زمني داخل كل دفعة.

## 7. Definition of Done لكل EXEC
- كل عنصر تنفيذي مرتبط صراحةً بـREQ وSPEC.
- حدود الملكية ومصدر الحقيقة محفوظة.
- لا DEC مفتوحة حُسمت ضمنياً.
- لا تغيير في Stage 3–6.
- لا API/DB/schema/UI/provider/framework lock-in إلا إذا فتحته مهمة تنفيذية لاحقة صراحةً.
- وجود اختبارات مناسبة لما تم تنفيذه قبل إعلان الدفعة مكتملة.
- وجود REVIEW عندما تكون الدفعة حساسة أو مالية أو صحية أو أمنية أو عندما تنص SPEC.
- تسجيل ما بقي خارج النطاق بسبب DEC/Research.
- إنشاء Achievement فقط لما اكتمل فعلياً.

## 8. قواعد عدم اختراع القرارات
1. المنفذ لا يحسم DEC-0001..0013.
2. إذا واجه قراراً مفتوحاً: يسجله ويحدد الجزء المتأثر ويوقفه فقط.
3. يكمل الأجزاء غير المتأثرة.
4. لا يضع default قانونياً/مالياً/صحياً ثم يعامله كحقيقة.
5. لا يضيف Concept أو Relationship إلى Stage 5 من داخل التنفيذ.
6. لا ينقل Source of Truth إلى طبقة تنفيذية أو Agent أو Device أو Derived View.
7. أي اختيار تقني يجب أن يبقى قابلاً للاستبدال ولا يعيد تعريف المجال.
