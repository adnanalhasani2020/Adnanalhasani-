# مركز قرارات المدير — مواصفات النموذج الأولي

## الهدف
توفير نقطة واحدة يختار منها مدير المؤسسة نشاطها الرئيسي، ويراجع السياسات التي تتطلب قرارًا بشريًا، ويُظهر النظام بوضوح الفرق بين **تفضيل مقترح** و**سياسة معتمدة**.

## الوضع الحالي
- النموذج المرئي: `docs/prototypes/admin-decision-settings.html`.
- النموذج مستقل وغير متصل بواجهة خلفية أو قاعدة بيانات.
- الحفظ محلي في المتصفح للعرض التجريبي فقط.
- لا تستخدم الصفحة لتخزين بيانات مرضى أو بيانات شخصية حساسة أو كلمات مرور.
- قد تبقى الاختيارات في `localStorage` على الجهاز حتى حذفها من زر إعادة الضبط أو مسح بيانات الموقع؛ لا تستخدم النموذج على جهاز مشترك.
- لا يُفعّل أي اختيار وحدات أو صلاحيات أو سياسة مالية.

## القرارات المعروضة
1. **النشاط الرئيسي:** تجارة وخدمات يومية، صحة، تعليم، خدمات مالية، مختلط، أو آخر. التجارة والخدمات اليومية هي الأولوية الحالية حسب DEC-0010؛ اختيار قطاع آخر لا يعدل القرار الاستراتيجي المعتمد.
2. **النطاق الصحي:** إبقاء الطبيب/المختبر/الدواء مؤجلًا، أو طلب مراجعة واعتماد رسمي للنطاق. وثيقة EXEC-0006 تستبعد هذه المفاهيم صراحة في الوضع الحالي.
3. **السياسات المالية:** إبقاء القرارات غير المحسومة محجوبة، أو فتح مراجعة رسمية. لا يجوز للاختيار أن يغير العملات المدعومة أو الدقة أو التسوية أو قواعد القيود تلقائيًا.
4. **الموافقة والتدقيق:** خيارات تفضيل للنقاش، لا تستبدل نظام التفويض الفعلي أو متطلبات التدقيق.

## متطلبات الإنتاج قبل الدمج في التطبيق
- واجهة خلفية ومخزن إعدادات مؤسسي مع ترحيل قاعدة بيانات إذا لزم.
- التحقق من هوية المدير وصلاحياته على مستوى الخادم، لا الواجهة فقط.
- سجل تدقيق غير قابل للتلاعب يتضمن القيمة السابقة والجديدة والفاعل والوقت وسبب التغيير.
- سير اعتماد للقرارات الحساسة: مسودة ← مراجعة ← اعتماد/رفض ← تفعيل مضبوط الإصدار.
- إظهار أثر القرار والميزات التابعة والمخاطر والاختبارات المطلوبة قبل الاعتماد.
- عدم تفعيل أي قرار صحي أو مالي مخالف للمواصفات أو يتجاوز القرارات المعتمدة.
- اختبارات للصلاحيات، وسلامة التزامن، وإعادة المحاولة، ورفض التغييرات غير المصرح بها.
- واجهة عربية RTL وإتاحة استخدام لوحة المفاتيح وقارئات الشاشة.

## معايير القبول
- يستطيع المدير معاينة الاختيارات قبل الإرسال.
- لا يتم تطبيق أي تغيير مؤثر قبل اعتماد صريح من جهة مخولة.
- لا يرفع اختيار نشاط ما حدود النطاق المعتمدة أو يتجاوز سياسة الحوكمة.
- تظهر حالة القرار بوضوح: غير مقدم، بانتظار المراجعة، معتمد، مرفوض، أو مفعّل.
- تُسجل جميع التغييرات المعتمدة في سجل تدقيق.
- لا يُعرض النموذج التجريبي على أنه واجهة إنتاج أو تكامل فعلي.

## الخطوة التالية
مراجعة التصميم مع صاحب المنتج، وتحديد مكانه في واجهة الإدارة الفعلية، ومصدر إعدادات المؤسسة، ومصفوفة الأدوار المعتمدة قبل بناء API أو حفظ إعدادات تشغيل حقيقية.
