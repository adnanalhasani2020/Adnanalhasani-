# EXEC-0019 — Persisted communication message entry/read path

## Evidence of gap
- The domain model in `src/agent_core/domain_communication.py` provides an in-memory Message model only.
- The relational schema already defines `conversations` and `messages`, including conversation state, sender person/reference, message type, content reference, state, and timestamps.
- Existing `tests/test_stage16_message_lifecycle.py` covers only the in-memory draft/send/revoke model; it does not exercise persistence through the relational tables.
- The operations map names general communication as a supported domain operation (REQ-0030–0032 / SPEC-0013 and SPEC-0026).

## Implemented behavior
- Persist a message only for an existing active conversation.
- Require either an active persisted sender Person or a non-empty sender reference.
- Require explicit message type and content reference; store the reference, not assumed transport payload.
- Read one persisted message and list conversation messages in deterministic event-time order.

## Boundaries
- No message transport/delivery, notification dispatch, read receipt, participant authorization, edit/delete policy, or conversation membership mutation is introduced.
- Existing schema states (`active`, `edited`, `deleted`) remain unchanged.
