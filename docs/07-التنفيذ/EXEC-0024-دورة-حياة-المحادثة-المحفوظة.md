# EXEC-0024 — Persisted Conversation lifecycle

## Evidence of gap
- The existing relational schema defines `conversations` and its `active`, `closed`, and `archived` states.
- The persisted message application requires an existing active Conversation, but no dedicated application service was found to create, restore, list, close, or archive Conversation records.

## Implemented capability
- Create a Conversation with explicit context reference and conversation type.
- Restore a Conversation by ID and list Conversations for an explicit context in deterministic order.
- Persist the existing close/archive state values and update timestamp.

## Boundaries
- Uses the existing schema; no migration.
- Does not add participants, membership, authorization, message delivery, notification, or read-receipt behavior.
- Does not define new lifecycle states or infer that context references grant access.
