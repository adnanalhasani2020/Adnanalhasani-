# EXEC-0025 — Persisted Activity and Membership operations

## Evidence of gap
- The relational schema defines `activities` and `memberships`, including explicit persisted states, effective periods, and version numbers.
- `ActivityApplication` in `src/agent_core/application.py` only creates in-memory Activity and Membership objects; it does not persist them or provide durable membership queries.

## Implemented capability
- Create and restore Activity records against an existing Person.
- Persist Membership records with explicit Person, Activity, state, and effective period.
- List memberships by Activity or Person with deterministic ordering and database-backed scope filters.
- Validate referenced records, UUIDs, timestamps, state values, and effective-period ordering.

## Boundaries
- Uses existing schema; no migration or inferred state transitions.
- A Membership or Role Assignment is not authorization; context/ownership references do not grant access.
- No automatic Role Assignment, authorization grant, notification, or other domain side effect is created.
