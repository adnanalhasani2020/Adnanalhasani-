# EXEC-0030 — عمليات العضوية المحفوظة

## الفجوة
يوفر المخطط جدول `memberships` مرتبطًا بـPerson وActivity، لكن المسار التطبيقي الحالي لم يوفر عمليات مستقلة لحفظ العضوية واستعادتها وسردها ضمن نطاق الشخص أو النشاط.

## التسليم
- إنشاء سجل Membership صريح يربط Person موجودًا بنشاط موجود.
- استعادة سجل حسب المعرّف، وسرد العضويات حسب Person أو Activity بترتيب حتمي.
- التحقق من UUID، الحالات المعروفة في نموذج Membership (`proposed`, `active`, `suspended`, `ended`)، timestamps ذات المنطقة الزمنية، وفترة الفعالية.
- استخدام المخطط الحالي دون ترحيل جديد.

## الحدود
- لا يقبل دعوات النشاط تلقائيًا ولا يربط الدعوة بعضوية تلقائيًا.
- لا يضيف انتقالات دورة حياة أو تفويضًا أو منح صلاحيات.
- لا ينشئ Role Assignment تلقائيًا ولا يستنتج وصولًا من العضوية.
- لا يحسم DEC أو أي عقد اعتماد غير محسوم.

## التنفيذ والاختبارات
- التنفيذ: `src/agent_core/membership_application.py`
- الاختبارات السلوكية: `tests/test_stage44_membership_persistence.py`
- التغطية: الاستمرارية بعد إعادة الفتح، السرد المقيد بالشخص/النشاط والترتيب الحتمي، المراجع المفقودة، UUID/الحالة/التوقيت غير الصالح، وفترة فعالية معكوسة.

## التتبع
مخطط `memberships` الحالي → `MembershipApplication` → `tests/test_stage44_membership_persistence.py`.
