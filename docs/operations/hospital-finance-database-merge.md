# دمج قاعدة المستشفى والمالية بأمان

الأداة `scripts/merge_hospital_finance_databases.py` تنشئ ملف SQLite جديدًا يحتوي مخططي Hospital وFinance وبياناتهما الحالية. لا تستبدل ملفات المصدر ولا تغيّرها.

## قبل التشغيل

1. أوقف خدمتي Hospital وFinance وخذ نسخة احتياطية من الملفين.
2. حدّد المسارين الحقيقيين لقاعدتي البيانات؛ لا تفترض أن أسماء الملفات أو مواقعها واحدة في كل بيئة.
3. شغّل الأمر من جذر المستودع وببيئة Python التي تحتوي متطلبات المشروع.

## مثال

```bash
python scripts/merge_hospital_finance_databases.py \
  --hospital /absolute/path/hospital.sqlite3 \
  --finance /absolute/path/commercial-mvp.sqlite3 \
  --output /absolute/path/shared-hospital-finance.sqlite3
```

يجب ألا يكون ملف الإخراج موجودًا مسبقًا. بعد النجاح، راجع تقرير JSON وأعداد الصفوف وفحوصات سلامة SQLite والمفاتيح الخارجية، ثم حدّث إعداد `APP_DB_PATH` في خدمتي Hospital وFinance إلى **المسار المطلق نفسه** بعد أخذ نسخة احتياطية وخطة رجوع.

## ضمانات وحدود

- يفتح ملفات المصدر للقراءة فقط ولا يكتب إليها.
- يرفض الكتابة فوق ملف إخراج موجود.
- يهيئ مخططي التطبيقين باستخدام مسارات التهيئة والترحيل المعتادة.
- يحافظ على قيم المعرفات والسجلات التاريخية وoutbox، ولا يخترع ربطًا بين معرفات المرضى وأشخاص Finance.
- يرفض اختلاف بنية الجدول أو تعارض قيود التفرد عندما تختلف بيانات الصف؛ لا يتجاوز التعارضات بصمت.
- يتجاهل فقط سجل `schema_migrations` الخاص بالمصدر، لأن مخطط الإخراج يسجّل ترحيلاته بنفسه.
- يوقف العملية عند انتهاك سلامة أو مفتاح خارجي. لا تحذف قواعد المصدر بعد النجاح.
- هذه الأداة تنقل صفوف قاعدة البيانات فقط؛ لا تحل تلقائيًا تعارض الهوية بين مرضى Hospital وأشخاص Finance ولا تقرر سياسات محاسبية.

جرّبها أولًا على نسخ احتياطية من قواعدك الفعلية. نجاح الأداة على ملفات تجريبية لا يعني أن قواعد الإنتاج نُقلت بالفعل.
