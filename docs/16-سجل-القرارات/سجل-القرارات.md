# سجل القرارات

**المعرف:** DOC-ADR-0001

## ADR-0001 — حوكمة المعرفة جزء من بنية المشروع
- التاريخ: 2026-10-07
- المشكلة: خطر الاعتماد على ذاكرة محادثة أو وكيل واحد وتحول الاقتراحات إلى حقائق.
- الخيارات: وثائق وصفية فقط / سجلات بسيطة / حوكمة معرفة مع حالات ومصدر حقيقة وتتبع وبوابات.
- الأدلة: متطلبات صاحب المشروع وتحليل خطر إعادة العمل والتناقض.
- القرار: الخيار الثالث.
- الآثار: توثيق أكثر بقليل مقابل قابلية تتبع أعلى.
- المخاطر: البيروقراطية؛ تعالج بالبساطة.
- الحالة: نهائي لهذه المرحلة.

## ADR-0002 — SQLite تخزين محلي مستهدف لا التزام نهائي
- التاريخ: 2026-10-07
- المشكلة: الحاجة لتخزين محلي مع عدم اكتمال دراسة المزامنة والتوسع.
- الخيارات: قاعدة نهائية / رفضها / تخزين محلي مستهدف للدراسة والمرحلة الأولى.
- الأدلة: طلب صاحب المشروع؛ الدراسات التقنية لم تبدأ بعد.
- القرار: الخيار الثالث.
- السبب: يحفظ مطلب التخزين المحلي ولا يغلق الخيارات المستقبلية.
- الحالة: نهائي لهذه المرحلة.

## ADR-0003 — بوابات تمنع الانتقال التلقائي

## ADR-0004 — الذكاء الاصطناعي ليس مصدراً للحقيقة

## ADR-0005 — فتح مرحلة البحث والأدلة بعد إغلاق فهم المجال
- التاريخ: 2026-10-07
- السياق: فهم المجال منفذ ومراجع داخلياً، وصدر أمر صريح بالانتقال إلى البحث والأدلة.
- القرار: إغلاق بوابة فهم المجال وفتح بوابة البحث والأدلة، مع إبقاء المتطلبات النهائية والمعمارية ونموذج البيانات والتنفيذ مغلقة.
- القيود: لا يتحول الدليل إلى قرار استراتيجي تلقائياً، ولا يبدأ البحث التقني التفصيلي إلا بقدر فهم خطر مجال.
- الحالة: نهائي لهذه المرحلة.

## DEC-0001 — اليمن كسوق مرجعي أول
- **التاريخ:** 2026-10-08
- **نوع القرار:** قرار صاحب المشروع.
- **القرار:** اليمن هو الدولة/السوق المرجعي الأول للنظام.
- **الحالة:** **DECIDED / RESOLVED**.
- **نطاق القرار:** يحدد اليمن كسوق مرجعي أول لتفسير القيود والسياق المحلي عند الحاجة.
- **حدود القرار:** لا يعني حصر النظام جغرافياً في اليمن مستقبلاً، ولا يمنع دعم أسواق أخرى لاحقاً.
- **الأثر الحالي:** توثيقي وحوكمي فقط؛ لا تعديل للكود أو Domain Model أو Architecture.
- **التتبع:** أي أثر لاحق على المتطلبات وSPECs المرتبطة بـDEC-0001 يحتاج مراجعة أثر موثقة قبل التنفيذ.
- **قرارات أخرى:** لا يحسم DEC-0002..DEC-0013 تلقائياً.
- **التوصيات السابقة:** لا تُرفع أي Recommendation سابقة إلى Decision بسبب هذا القرار.

## DEC-0002 — Primary Account
- **التاريخ:** 2026-10-08
- **نوع القرار:** قرار صاحب المشروع.
- **القرار:** الخيار الثاني — **تجميع منطقي غير مالك**.
- **الحالة:** **DECIDED / RESOLVED**.
- **حدود القرار:** تسجيل الخيار الثاني كما ورد في بطاقة DEC-0002، دون إعادة تفسير أو إضافة تفاصيل لم تكن في الخيار الأصلي.
- **الالتباس:** لا يوجد؛ تمت مطابقة الخيار الثاني حرفياً مع بطاقة القرار الحالية.
- **الأثر الحالي:** توثيقي وحوكمي فقط؛ لا تعديل للكود أو Domain Model أو Architecture.
- **التتبع:** المتطلبات المتأثرة هي REQ-0002 وREQ-0017، وSPECs المتأثرة هي SPEC-0001 وSPEC-0007 وSPEC-0009؛ هذا تسجيل للأثر فقط وليس اعتماداً تنفيذياً.
- **قرارات أخرى:** لا يحسم أي DEC آخر.
- **التوصيات السابقة:** لا تُرفع أي Recommendation إلى Decision بسبب هذا القرار.

## DEC-0003 — الدور المالي للنظام
- **التاريخ:** 2026-10-08
- **نوع القرار:** قرار صاحب المشروع.
- **القرار:** الخيار 2.
- **المعنى:** النظام يشارك في إنشاء وإدارة الالتزامات والمدفوعات والتسويات ضمن النظام، مع بقاء المسؤولية القانونية لدى الأطراف وفق القواعد والاختصاصات التي سيتم تحديدها لاحقاً.
- **الحالة:** **DECIDED / RESOLVED**.
- **حدود القرار:** لا يعني أن النظام مؤسسة مالية أو بنكاً أو جهة تسوية قانونية؛ ولا يحسم المتطلبات القانونية المحلية تلقائياً.
- **قيود التنفيذ:** لا Financial Orchestration Engine الآن، ولا تغييرات كود؛ التفاصيل القانونية والتنظيمية خاضعة للبحث والقرارات اللاحقة.
- **التتبع:** المتطلبات المتأثرة مباشرة هي REQ-0019 وREQ-0020 وREQ-0029 وREQ-0037 وREQ-0063، وSPECs المتأثرة مباشرة هي SPEC-0007 وSPEC-0008 وSPEC-0009 وSPEC-0025؛ تسجيل الأثر لا يعني اعتماد تنفيذها.
- **قرارات أخرى:** لا يحسم أي DEC آخر.
- **التوصيات السابقة:** لا تُرفع أي Recommendation إلى Decision بسبب هذا القرار.

## DEC-0006 — سلطة الوكيل المالية
- **التاريخ:** 2026-10-08
- **نوع القرار:** قرار صاحب المشروع.
- **القرار:** سلطة الوكيل المالي يتم ضبطها من شاشة إعدادات مخصصة.
- **المبدأ المعتمد:** **User-configured Agent Authority**.
- **الحالة:** **DECIDED / RESOLVED**.
- **القيود المعتمدة:** **User Configuration ≠ Unlimited Financial Authority**؛ إعداد المستخدم لا يلغي Authorization، أو Approval requirements إن كانت مطلوبة، أو القيود القانونية والتنظيمية، أو حدود الحسابات والأموال، أو سياسات النظام، أو قيود الأمان.
- **حدود التنفيذ:** لا تُنفذ Agent Authority Settings في الكود الآن.
- **GAPs:** لا يُنفذ GAP-0001 أو GAP-0003 أو GAP-0004 بهذا القرار.
- **التتبع:** المتطلبات المتأثرة هي REQ-0042 وREQ-0043 وREQ-0044 وREQ-0045، وSPECs المتأثرة هي SPEC-0017 وSPEC-0018؛ تسجيل الأثر لا يعني اعتماد تنفيذها.
- **قرارات أخرى:** لا يحسم أي DEC آخر.
- **التوصيات السابقة:** لا تُرفع أي Recommendation إلى Decision بسبب هذا القرار.

## DEC-0007 — حدود AI الصحية
- **التاريخ:** 2026-10-08
- **نوع القرار:** قرار صاحب المشروع.
- **القرار:** حدود وسلطة AI الصحية يتم ضبطها من إعدادات المستخدم.
- **المبدأ المعتمد:** **User Configuration ≠ Unlimited Authority**.
- **الحالة:** **DECIDED / RESOLVED**.
- **القيود المعتمدة:** إعداد المستخدم لا يمكنه تجاوز القيود القانونية والتنظيمية، أو قيود السلامة، أو سياسات النظام، أو حدود الصلاحيات، أو القيود السريرية المعتمدة.
- **حدود السلطة:** لا يُعتبر AI تلقائياً صاحب القرار السريري النهائي.
- **حدود التنفيذ:** لا تُنفذ هذه الإعدادات في الكود الآن.
- **المستقبل:** التفاصيل الدقيقة لدرجات الاستقلالية والحدود تحتاج لاحقاً إلى مواصفات/بحث مناسب.
- **التتبع:** المتطلبات المتأثرة هي REQ-0026 وREQ-0042 وREQ-0043 وREQ-0045 وREQ-0066، وSPECs المتأثرة هي SPEC-0010 وSPEC-0011 وSPEC-0017 وSPEC-0018 وSPEC-0020؛ تسجيل الأثر لا يعني اعتماد تنفيذها.
- **قرارات أخرى:** لا يحسم أي DEC آخر.
- **التوصيات السابقة:** لا تُرفع أي Recommendation إلى Decision بسبب هذا القرار.

## DEC-0010 — التجارة والخدمات اليومية كأولوية أولى
- **التاريخ:** 2026-10-08
- **نوع القرار:** قرار صاحب المشروع.
- **القرار:** الأولوية الأولى للنظام هي **التجارة والخدمات اليومية**.
- **التوضيح:** الصحة والتعليم والمال تبقى ضمن نطاق النظام العام؛ القرار يحدد أولوية ترتيب مراحل التنفيذ والموارد والـMVP/الإصدارات الأولى فقط.
- **الحالة:** **DECIDED / RESOLVED**.
- **حدود القرار:** لا يلغي الصحة أو التعليم أو المال، ولا يستنتج تفاصيل تنفيذية غير معتمدة، ولا يغيّر Architecture أو Data Model أو التنفيذ في هذه الدفعة.
- **الأثر الحالي:** توثيقي وحوكمي فقط؛ لا تعديل للكود أو Domain Model أو Architecture.
- **التتبع:** المتطلبات المتأثرة مباشرة هي REQ-0027 وREQ-0029 وREQ-0033، وSPECs المتأثرة مباشرة هي SPEC-0012 وSPEC-0014 وSPEC-0025؛ هذا تسجيل للأثر فقط وليس اعتماداً أو تنفيذاً لها.
- **قرارات أخرى:** لا يحسم DEC-0002..DEC-0009 أو DEC-0011..DEC-0013 تلقائياً.
- **التوصيات السابقة:** لا تُرفع أي Recommendation سابقة إلى Decision بسبب هذا القرار.

## DEC-0004 — تفويض عائلي واضح ومحدود بالصلاحيات
- **التاريخ:** 2026-10-08
- **نوع القرار:** قرار صاحب المشروع.
- **القرار:** الخيار 1 — تفويض عائلي واضح ومحدود بالصلاحيات.
- **المبدأ المعتمد:** **Family Relationship ≠ Delegation ≠ Authorization**.
- **الحالة:** **DECIDED / RESOLVED**.
- **القواعد المعتمدة:** العلاقة الأسرية وحدها لا تمنح صلاحية وصول تلقائية؛ يمكن لشخص بالغ إدارة أو التصرف نيابة عن فرد آخر عند وجود تفويض/أهلية مناسبة؛ التفويض محدد النطاق والغرض والصلاحيات؛ يمكن تقييده أو إلغاؤه وفق القواعد المعتمدة لاحقاً؛ الاطلاع لا يعني تلقائياً التعديل أو التنفيذ؛ الشؤون المالية والصحية وغيرها لا تصبح متاحة لمجرد العلاقة الأسرية؛ الأطفال والحالات التي تتطلب حماية خاصة تحتاج قواعد أهلية مناسبة لاحقاً.
- **حدود القرار:** لا تُستنتج تفاصيل قانونية أو عمرية غير معتمدة، ولا تُحسم قواعد الأهلية التفصيلية بهذا القرار.
- **الأثر الحالي:** توثيقي وحوكمي فقط؛ لا تعديل للكود أو Domain Model أو Architecture.
- **قرارات أخرى:** لا يحسم DEC-0002..DEC-0003 أو DEC-0005..DEC-0013 تلقائياً.
- **التوصيات السابقة:** لا تُرفع أي Recommendation سابقة إلى Decision بسبب هذا القرار.
