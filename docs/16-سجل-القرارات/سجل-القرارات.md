## ADR-0001 — حوكمة المعرفة جزء من بنية المشروع
- التاريخ: 2026-10-07
- المشكلة: خطر الاعتماد على ذاكرة محادثة أو وكيل واحد وتحول الاقتراحات إلى حقائق.
- الخيارات: وثائق وصفية فقط / سجلات بسيطة / حوكمة معرفة مع حالات ومصدر حقيقة وتتبع وبوابات.
- الأدلة: متطلبات صاحب المشروع وتحليل خطر إعادة العمل والتناقض.
- القرار: الخيار الثالث.
- الآثار: توثيق أكثر بقليل مقابل قابلية تتبع أعلى.
- المخاطر: البيروقراطية؛ تعالج بالبساطة.
- الحالة: نهائي لهذه المرحلة.

## ADR-0002 — SQLite تخزين محلي مستهدف لا التزام نهائي

- القرار: الخيار الثالث.

- الحالة: نهائي لهذه المرحلة.

## ADR-0005 — فتح مرحلة البحث والأدلة بعد إغلاق فهم المجال
- التاريخ: 2026-10-07
- السياق: فهم المجال منفذ ومراجع داخلياً، وصدر أمر صريح بالانتقال إلى البحث والأدلة.
- القرار: إغلاق بوابة فهم المجال وفتح بوابة البحث والأدلة، مع إبقاء المتطلبات النهائية والمعمارية ونموذج البيانات والتنفيذ مغلقة.
- القيود: لا يتحول الدليل إلى قرار استراتيجي تلقائياً، ولا يبدأ البحث التقني التفصيلي إلا بقدر فهم خطر مجال.
- الحالة: نهائي لهذه المرحلة.

## DEC-0001 — اليمن كسوق مرجعي أول
- **التاريخ:** 2026-10-08
- **نوع القرار:** قرار صاحب المشروع.
- **القرار:** اليمن هو الدولة/السوق المرجعي الأول للنظام.
- **الحالة:** **DECIDED / RESOLVED**.
- **نطاق القرار:** يحدد اليمن كسوق مرجعي أول لتفسير القيود والسياق المحلي عند الحاجة.
- **حدود القرار:** لا يعني حصر النظام جغرافياً في اليمن مستقبلاً، ولا يمنع دعم أسواق أخرى لاحقاً.
- **الأثر الحالي:** توثيقي وحوكمي فقط؛ لا تعديل للكود أو Domain Model أو Architecture.
- **التتبع:** أي أثر لاحق على المتطلبات وSPECs المرتبطة بـDEC-0001 يحتاج مراجعة أثر موثقة قبل التنفيذ.
- **قرارات أخرى:** لا يحسم DEC-0002..DEC-0013 تلقائياً.
- **التوصيات السابقة:** لا تُرفع أي Recommendation سابقة إلى Decision بسبب هذا القرار.

## DEC-0003 — الدور المالي للنظام
- **التاريخ:** 2026-10-08
- **نوع القرار:** قرار صاحب المشروع.
- **القرار:** الخيار 2.
- **المعنى:** النظام يشارك في إنشاء وإدارة الالتزامات والمدفوعات والتسويات ضمن النظام، مع بقاء المسؤولية القانونية لدى الأطراف وفق القواعد والاختصاصات التي سيتم تحديدها لاحقاً.
- **الحالة:** **DECIDED / RESOLVED**.
- **حدود القرار:** لا يعني أن النظام مؤسسة مالية أو بنكاً أو جهة تسوية قانونية؛ ولا يحسم المتطلبات القانونية المحلية تلقائياً.
- **قيود التنفيذ:** لا Financial Orchestration Engine الآن، ولا تغييرات كود؛ التفاصيل القانونية والتنظيمية خاضعة للبحث والقرارات اللاحقة.
- **التتبع:** المتطلبات المتأثرة مباشرة هي REQ-0019 وREQ-0020 وREQ-0029 وREQ-0037 وREQ-0063، وSPECs المتأثرة مباشرة هي SPEC-0007 وSPEC-0008 وSPEC-0009 وSPEC-0025؛ تسجيل الأثر لا يعني اعتماد تنفيذها.
- **قرارات أخرى:** لا يحسم أي DEC آخر.
- **التوصيات السابقة:** لا تُرفع أي Recommendation إلى Decision بسبب هذا القرار.

## DEC-0006 — سلطة الوكيل المالية
- **التاريخ:** 2026-10-08
- **نوع القرار:** قرار صاحب المشروع.
- **القرار:** سلطة الوكيل المالي يتم ضبطها من شاشة إعدادات مخصصة.
- **المبدأ المعتمد:** **User-configured Agent Authority**.
- **الحالة:** **DECIDED / RESOLVED**.
- **القيود المعتمدة:** **User Configuration ≠ Unlimited Financial Authority**؛ إعداد المستخدم لا يلغي Authorization، أو Approval requirements إن كانت مطلوبة، أو القيود القانونية والتنظيمية، أو حدود الحسابات والأموال، أو سياسات النظام، أو قيود الأمان.
- **حدود التنفيذ:** لا تُنفذ Agent Authority Settings في الكود الآن.
- **GAPs:** لا يُنفذ GAP-0001 أو GAP-0003 أو GAP-0004 بهذا القرار.
- **التتبع:** المتطلبات المتأثرة هي REQ-0042 وREQ-0043 وREQ-0044 وREQ-0045، وSPECs المتأثرة هي SPEC-0017 وSPEC-0018؛ تسجيل الأثر لا يعني اعتماد تنفيذها.
- **قرارات أخرى:** لا يحسم أي DEC آخر.
- **التوصيات السابقة:** لا تُرفع أي Recommendation إلى Decision بسبب هذا القرار.

## DEC-0009 — Available Nearby

- **التتبع:** REQ-0016 وREQ-0033 وREQ-0034 وREQ-0035؛ SPEC-0006 وSPEC-0014. تسجيل الأثر لا يعني اعتماد تنفيذ.

## DEC-0011 — Offline Financial Operations
- **التاريخ:** 2026-10-08
- **نوع القرار:** قرار صاحب المشروع.
- **القرار:** لا يسمح النظام بتنفيذ أو إنشاء العمليات المالية عندما لا يتوفر الإنترنت.
- **المبدأ:** **Financial operations require connectivity.**
- **الحالة:** **DECIDED / RESOLVED**.
- **القواعد:** لا عملية مالية نهائية Offline؛ لا Payment/Settlement/Transfer مالي كعملية قابلة للتنفيذ Offline؛ يمكن استخدام الواجهة/التحضير فقط إذا كان ذلك مناسباً، لكن لا اعتماد للعملية المالية بدون اتصال.
- **المبدأ الحدّي:** **Offline ≠ Financial Finality**.
- **حدود التنفيذ:** لا Financial Offline Engine.
- **التتبع:** REQ-0022 وREQ-0046 وREQ-0056 وREQ-0063؛ SPEC-0008 وSPEC-0019 وSPEC-0023 وSPEC-0024. تسجيل الأثر لا يعني اعتماد تنفيذ.

## أثر القرارات على الحالة التنفيذية اللاحقة — 2026-10-08

لا توجد Decision Dependencies جديدة في هذه التسوية. القرارات DEC-0001..DEC-0013 تبقى **13/13 DECIDED / RESOLVED**.

- **DEC-0010** يظل المرجع الاستراتيجي لترتيب الأولويات: **Commerce + Daily Services** هي الأولوية الأولى للمشروع. Financial Orchestration ليس الهدف العام للمشروع.
- **DEC-0011** و**DEC-0013** وغيرها من القرارات المعتمدة استُهلك أثرها حيث كان ضمن النطاق التنفيذي؛ لا يعني ذلك فتح capability جديدة تلقائياً.
- قرارات Stage 11 الخاصة بـGAP-0001/GAP-0003 وStage 12 الخاصة بـGAP-0004 محفوظة في سجلاتها المرحلية، ولا تغيّر قائمة DEC-0001..DEC-0013.
- Stage 12A أثبت recognition/orchestration ضمن النطاق المعتمد. Durable Financial Workflow بقي deferred؛ ولا توجد حاجة إلى Decision Dependency جديدة لأن تصميم Stage 12 سبق أن فصل GAP-0005 operation durability عن independent durable workflow state.

## DEC-0014 — Risk-tiered Agent Autonomy
- **التاريخ:** 2026-10-08
- **نوع القرار:** قرار صاحب المشروع.
- **المتطلب المحسوم:** REQ-FUNC-0043.
- **السؤال:** ما مستويات استقلالية الوكيل بين الاقتراح والتحضير والتنفيذ المفوض، وما الذي يحدد مستوى التحكم المطلوب؟
- **القرار:** **Risk-tiered autonomy** — استقلالية الوكيل مرتبطة بالفعل ومصنفة حسب المخاطر، وليست سلطة تنفيذ عامة.
- **المستويات المعتمدة:**
  1. **Proposal:** الوكيل يقترح فقط ولا ينتج أثراً تنفيذياً.
  2. **Preparation:** الوكيل يجهز العملية/البيانات/الخطوات، دون أثر خارجي أو التزام نهائي إلا بعد السماح المطلوب.
