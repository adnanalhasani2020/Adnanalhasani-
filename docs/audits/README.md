## نتائج مهمة معروفة في 2026-10-26

- **سلامة سند المصروف:** حارس الالتزام المؤجل كان يثبت التوازن والنشر فقط؛ أُضيفت شروط في Git لربط القيد بمصدر السند ومطابقة العملة والمبلغ. حالة النشر تحتاج تحققًا بعد تطبيق migration.

- **RLS لاستلام المخزون وإعادة تخزين المرتجعات:** اكتُشفت سياستان إضافيتان بمقارنة ذاتية لمؤسسة العضوية؛ نُشر إصلاحهما على Supabase الحي وتأكدت صحة الشروط من `pg_policies`.

- **RLS ربط حساب العميل:** إصلاح شرط عزل المؤسسات نُشر على Supabase الحي وتحققنا من `pg_policies`.
- **التحصيل بعد المرتجعات:** جرى إصلاح حارسي التحصيل وGL في migration بالمستودع، لكن لم يُنشر الترحيل على Supabase الحي؛ لا تعتمد تحصيل فواتير لها مرتجعات حتى النشر والتحقق.
- **سندات المصروف:** طُبقت ترحيلات سجل إلغاء السند والتحقق من القيد العكسي وسلامة القيد عند الالتزام على Supabase الحي، وتم فحص أسماء الدوال/المشغلات بعد النشر.

1. **المديونيات:** تم إصلاح نموذج العرض ليحسب الرصيد بعد الاستردادات النقدية المنفذة وخصومات المرتجعات المعتمدة، ويعرض هذه القيم منفصلة. يوجد حارس خادمي للتحصيل في migration، لكن نجاح CI والتطبيق على Supabase الحي يجب التحقق منهما كلٌّ على حدة.
2. **الكميات الكسرية:** ما زالت فجوة مؤكدة في واجهة تركيب فاتورة البيع ونموذج المخزون؛ النوع `Int` والتحقق الرقمي يمنعان الكميات العشرية. الإصلاح الشامل يتطلب توافقًا بين الواجهة ونموذج البيانات وRPC والمخزون والاختبارات.
3. **التقارير المالية:** لا تُعلن جاهزية ميزان مراجعة أو قائمة دخل أو ميزانية أو تسوية بنكية لمجرد وجود شاشة أو جدول؛ يلزم إثبات الربط مع القيود المنشورة ومصادر الأرصدة.
4. **المستودعات:** وجود تعريف لمواقع التخزين لا يثبت أن الأرصدة وحركات النقل تعمل على مستوى الموقع.
5. **بيئة Supabase:** وجود migration في Git لا يثبت أنها مطبقة في المشروع الحي.
6. **التوثيق:** يجب ربط أي ادعاء عن اكتمال ميزة بملفات الكود والاختبارات ونسخة migration والـcommit الذي جرى التحقق عليه.
