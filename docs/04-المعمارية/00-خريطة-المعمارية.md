# خريطة المعمارية

## الحالة
**مفتوحة وقيد التنفيذ — تعميق معماري، دون إغلاق.**

المرجع الحاكم للجولة: 0305a9d1aa63ba864f44c4d8926bccbff2979fd5.

## هدف الجولة
تعميق المعمارية الحالية لتصبح قابلة للمراجعة على مستوى المسؤوليات والحدود ومصادر الحقيقة والتدفقات والثوابت، قبل أي نموذج بيانات أو قرار تقني.

## ما تم تعميقه
- مسؤولية وداخل/خارج ومالك الحقيقة وقراءة/طلب تغيير ومغيرات الحالة وInvariants لكل مجال رئيسي.
- عشر تدفقات معمارية فعلية مع عبور الحدود ومصادر الحقيقة.
- النموذج المفاهيمي المالي وعلاقاته.
- السلسلة السريرية وفصلها عن السياق المالي.
- مراحل الوكيل وحدود التنفيذ والموافقة.
- تصنيف Offline إلى أربعة مستويات.
- Owner → Change Authority → Consumers → Derived Views.
- مصفوفة cross-domain ownership.
- تغطية 59/59 بــArchitectural Concerns فعلية.
- سجل تفصيلي لتأثير DEC-0001..DEC-0013.
- بدائل معمارية لا يجوز افتراضها مبكراً.

## النطاق
Identity, Access, Activities, Commerce, Inventory, Finance, Payments/Settlement, Health, Family/Delegation, Education, Communication, Discovery, Channels, Agents, Offline, Privacy/Security/Audit.

## قواعد ثابتة
- المتطلبات الـ59 ليست معتمدة تلقائياً.
- DEC-0001..DEC-0013 لا تُفترض.
- حدود المجال ≠ حدود الخدمات.
- Source of Truth ≠ نسخة مشتقة.
- لا DB/SQL/ERD/API/UI/Code/Framework/Cloud/Provider/Message Broker/Cache/Sync Algorithm.
- Offline ≠ Finality.
- Agent ≠ Domain Owner.
- Health/Finance/Identity/Authorization منفصلة دلالياً.

## حالة المرحلة
المعمارية **مفتوحة** وتحتاج مراجعة نهائية مستقلة. لا ACH، ولا انتقال تلقائي إلى المرحلة التالية.
