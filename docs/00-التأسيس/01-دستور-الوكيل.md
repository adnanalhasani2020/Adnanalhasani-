# دستور الوكيل

**الحالة:** قرار — **المعرف:** DOC-GOV-0001

قبل أي مهمة كبيرة يجب على الوكيل: قراءة الدستور، قراءة الفهرس، البحث عن الطلب السابق، البحث عن القرارات، البحث عن التنفيذ السابق، قراءة الوثائق المرتبطة، والتحقق من الأدلة العلمية والتقنية عند أهمية القرار.

ثم يحدد هل المطلوب جديد أم منفذ سابقاً. لا يعيد تنفيذ شيء سبق تنفيذه. لا يغير قراراً سابقاً دون توثيق السبب. يوثق كل إنجاز وكل قرار معماري مهم وكل تعديل جوهري، ويحدث الفهرس عند إضافة وثائق.

## قاعدة منع إعادة العمل
إذا طلب المستخدم شيئاً سبق تنفيذه، يقول الوكيل إن المهمة منفذة سابقاً ويذكر مكان التوثيق والتنفيذ بدلاً من إعادة البناء، إلا إذا طلب المستخدم تغييراً أو إصلاحاً صراحة.

## قاعدة المعرفة
«اقتراح» ليس «قراراً». «فرضية» ليست «حقيقة». «بحث مطلوب» ليس دليلاً. «منفذ» لا يعني «مراجع» ولا «معتمد». «مراجع» تعني أن العمل خضع لمراجعة مناسبة، ولا تعني الاعتماد النهائي. «معتمد» يعني موافقة الجهة المخولة. «مرفوض» لا يعاد اقتراحه دون مراجعة سبب الرفض.

## قاعدة التغيير
لا يحذف التاريخ. كل تغيير يربط الحالة الجديدة بالسابقة وسببه وتاريخه ومصدره.

## قاعدة الأدلة
القرارات المهمة لا تؤخذ من رأي الوكيل وحده؛ تستخدم مصادر مناسبة لطبيعة السؤال وتُسجل قوة الدليل وحدوده. الدليل الجديد لا يغير قراراً معتمداً بصمت؛ يخضع القرار لعملية مراجعة موثقة.

## قاعدة البوابات
اكتمال الملفات لا يفتح المرحلة التالية. الانتقال يحتاج شروط البوابة واعتمادها.

## قاعدة اللغة
الوثائق بالعربية. عند الحاجة: **المصطلح العربي (English Term)** مع تعريفه عند أول استخدام.

## التسلسل التشغيلي
**طلب → تحقق من السابق → فهم الحالة → بحث عند الحاجة → قرار → مواصفة → تنفيذ → مراجعة عند انطباقها → اختبار → إنجاز → تحديث السجلات.**
