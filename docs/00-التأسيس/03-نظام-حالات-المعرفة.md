# نظام حالات المعرفة

**الحالة:** قرار — **المعرف:** DOC-GOV-0002

| الحالة | التعريف |
|---|---|
| مطلوب | طلب صادر من صاحب المشروع ولم يتحول بالضرورة إلى قرار تصميم. |
| قرار | موقف معتمد يصبح مرجعاً حتى يُلغى أو يُستبدل. |
| اقتراح | فكرة لم تعتمد بعد. |
| فرضية | افتراض قابل للخطأ يحتاج تحققاً أو قياساً. |
| بحث مطلوب | سؤال يحتاج أدلة قبل اتخاذ قرار. |
| منفذ | تم تنفيذ العمل المرتبط به. لا يعني ذلك أنه مراجع أو معتمد. |
| مراجع | تمت مراجعة العمل وفق معيار مراجعة مناسب، مع توثيق نتيجة المراجعة عند انطباقها. لا يعني ذلك وحده أنه معتمد. |
| معتمد | تمت الموافقة على العمل من الجهة المخولة بالاعتماد. لا يعني ذلك أن كل عمل منفذ أو مراجع إلا إذا ثبت ذلك منفصلاً. |
| مرفوض | تم رفض الفكرة أو الخيار مع توثيق السبب. |
| ملغى | لم يعد مطلوباً أو صالحاً مع حفظ التاريخ. |
| مستبدل | حل محله قرار أو معلومة أحدث مع رابط للبديل. |

## قاعدة الفصل بين التنفيذ والمراجعة والاعتماد

**منفذ ≠ مراجع ≠ معتمد.**

قد يكون العمل منفذاً دون أن تتم مراجعته، وقد يكون مراجعاً دون أن يحصل على اعتماد نهائي، وقد يكون معتمداً في وثيقة أو قرار من دون أن يعني ذلك أن كل تنفيذ مرتبط به قد اكتمل.

## قواعد الانتقال

يجب تسجيل سبب الانتقال وتاريخه. مثال: اقتراح → قرار بعد اعتماد صريح؛ فرضية → قرار بعد تحقق مناسب؛ مطلوب → منفذ بعد التنفيذ؛ منفذ → مراجع بعد اكتمال المراجعة المناسبة؛ مراجع → معتمد بعد موافقة الجهة المخولة؛ قرار → مستبدل عند اعتماد بديل.

لا يجوز رفع اقتراح إلى قرار بصمت، أو اعتبار فرضية حقيقة، أو اعتبار التنفيذ دليلاً على المراجعة أو الاعتماد، أو حذف قرار قديم، أو اعتبار وجود ملف دليلاً على الاعتماد.
