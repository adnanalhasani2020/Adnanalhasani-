# TEST-0005 — Reliability, Edge Cases & State Consistency

**Baseline:** `a41a7e3480365bd729439073ba8deaf08bbfd03c`
**الحالة:** منفذة اختبارياً؛ الحكم النهائي مرتبط بـGitHub Actions على commit الدفعة نفسه.

## الهدف
اختبار موثوقية النموذج الحالي وحدود الحالات الطرفية واتساق الحالة والتاريخ ومصدر الحقيقة، دون إضافة أي منطق إنتاجي أو Architecture أو Domain Concept جديد.

## التنفيذ
- **47 اختباراً جديداً** في `tests/test_stage8_batch5.py`.
- الاختبارات السابقة لم تُعدّل.
- كامل suite هو المرجع: **166 اختباراً قبل الدفعة + 47 جديداً = 213 اختباراً**.
- لا Idempotency Engine، ولا Persistence/Registry، ولا Deduplication Engine، ولا Policy/Workflow/Orchestration/Reconciliation Engine.
- لا تغييرات على DEC-0001..DEC-0013.
- Stage 7 تبقى CLOSED، وStage 8 تبقى OPEN، وStage 9 لم تُفتح.

## محاور التغطية
1. القيم الفارغة والمفقودة وغير الصالحة والحدود والقيم القصوى والمنخفضة.
2. Identity: Person/Identifier/AccessAccount/FinancialAccount، duplicate Persons، إعادة استخدام Person عبر Activities.
3. Activity/Membership/Role مع temporal boundaries وGAP-0002.
4. Commerce/Inventory: Product/Offering/InventoryPosition/Availability/Sale/Invoice، transition enforcement، التكرار، والحفاظ على المراجع.
5. Finance: Invoice/Obligation/Payment/Settlement/FinancialTransaction/LedgerEntry/Balance، amounts، replay، cancellation/reversal، واشتقاق Balance.
6. Health: PatientContext/Encounter/ClinicalRecord/ResultReport/Prescription، correction/replay، والفصل عن Commerce/Finance/Agent.
7. PendingOperation/Conflict/Device: التسلسلات Pending → Conflict → Correction/Resolution، وعدم تحولها إلى Domain Truth.
8. Agent/Approval: التكرار، الفصل عن Domain Owner، وعدم استنتاج السلطة من Approval أو Agent.
9. Cross-domain ownership: Finance / Commerce / Health / Identity / Authorization / Agent، مع منع خلط الكيانات المشار إليها.
10. Failure isolation: فشل عملية لا يغير الحالة السابقة أو Source of Truth الموجود.
11. Historical records: التحقق من عدم قابلية تعديل الكائنات frozen، والتحقق أن correction يحافظ على الأصل والمراجع.

## GAP-0005 — Replay / Idempotency
الاختبار يثبت حدود التنفيذ الحالي:
- `is_duplicate()` مجرد boundary helper؛ لا registry ولا persistence ولا replay store.
- تكرار العملية لا يُمنع بشكل دائم على مستوى runtime.
- الاختبارات لا تفشل لمجرد غياب التنفيذ المقصود مستقبلاً؛ بل تثبت limitation الحالية.
- لا يُضاف أي Idempotency Engine في Batch 5.

## GAP-0006 — "الشخص يسجل مرة واحدة"
الاختبار يثبت:
- يمكن إنشاء Persons مستقلة حتى مع تطابق محتمل في الواقع.
- اختلاف Identifiers لا ينشئ Person جديدة تلقائياً في النموذج نفسه.
- يمكن ربط نفس Person بعدة Activities.
- لا توجد Identity Registry أو Deduplication Engine.
- لا يُحوّل هذا النقص إلى implementation ضمن Batch 5.

## النتائج المتوقعة/المقيسة
- enforced boundaries تبقى مرفوضة عند خرقها، مثل Sale completion قبل confirmation والقيم المالية غير الموجبة.
- transitions غير المحكومة حالياً تُسجل كـcurrent behavior/limitation، لا كـimplementation requirement.
- Balance يبقى مشتقاً من LedgerEntry.
- PendingOperation وConflict وDevice وAgent لا تصبح Domain Truth أو Domain Owner.
- correction/cancellation/reversal تحفظ IDs والمراجع والأصل حيث يفرض النموذج الحالي ذلك.
- لا mutation جزئي غير مقصود عند فشل العملية المختبرة.
