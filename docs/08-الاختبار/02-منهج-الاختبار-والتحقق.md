# منهج الاختبار والتحقق — Stage 8

**الحالة:** مفتوح — TEST-0001 منفذة، والحكم النهائي يعتمد على CI للـcommit الجديد.

## طبقات التحقق
### 1. Test
إثبات أن السلوك المنفذ يطابق ما يمكن اشتقاقه من SPEC وREQ.

### 2. Integration
التحقق من تفاعل الوحدات مع الحفاظ على حدود الملكية وSource of Truth.

### 3. Regression
التحقق من عدم كسر السلوك المتحقق سابقاً وعدم إدخال انحراف عن Stage 3–7.

### 4. Boundary / Negative Verification
اختبار ما يجب منعه أو رفضه، وليس فقط المسارات الناجحة.

### 5. Traceability
ربط كل نتيجة اختبار بما تغطيه من REQ/SPEC/EXEC، مع تسجيل الفجوات صراحةً.

### 6. Evaluation
تمييز:
- PASS.
- FAIL.
- BLOCKED بسبب DEC/Research.
- NOT APPLICABLE مع سبب موثق.

## قواعد التحقق
- لا تُعتبر نتيجة PASS حكماً على Domain Truth خارج نطاق الاختبار.
- لا يُصلح الاختبار فشلاً بإضعاف المعيار دون مراجعة موثقة.
- لا يُحوّل قرار مفتوح إلى default تقني أو وظيفي.
- القضايا الحساسة مالياً/صحياً/قانونياً تتطلب إبقاء حدود القرار صريحة.
- الاختيارات التقنية تبقى قابلة للاستبدال ما لم تُفتح صراحةً في دفعة مناسبة.

## تطبيق TEST-0001
- اختبارات تكامل حقيقية عبر أكثر من وحدة/مجال، وليست إنشاء objects منفردة فقط.
- Boundary / Negative verification للحالات التي يمكن إثباتها من التنفيذ الحالي.
- Regression يشمل كامل suite السابقة والجديدة عبر Workflow Stage 7 الموجود.
- لا mocks لإخفاء حدود Domain.
- أي سياسة غير مفروضة حالياً تُسجل GAP بدلاً من اختراع architecture جديدة.

## الأدوات
تم استخدام GitHub Actions الحالي؛ لا يُفرض framework جديد. لا يُعد TEST-0001 PASS إلا إذا نجح CI للـcommit نفسه.
