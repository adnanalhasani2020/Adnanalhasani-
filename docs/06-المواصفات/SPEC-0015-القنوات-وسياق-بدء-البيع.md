# SPEC-0015 — القنوات وسياق بدء البيع

## 1. الغرض والنطاق
تحدد هذه المواصفة معنى Channel Context كسياق بدء/تنفيذ تفاعل، وحدوده مع Sale وActivity وRole Assignment وAuthorization.
القواعد:
**Channel Context ليس Domain Owner.**
القنوات المختلفة مجرد طرق بدء التفاعل، وليست عمليات بيع مستقلة.
**Sale يبقى في Commerce / SPEC-0005.**
**Authorization يبقى في SPEC-0003.**
لا تضيف Channel أو Checkout كـConcept جديد؛ تستخدم Channel Context الموجود في Stage 5.

## 3. Dependencies
- SPEC-0002: Activity/Membership/Role context.
- SPEC-0005: Sale وCommerce behavior.
- Domain Constraint: Channel Context لا يملك Sale.
- External: DEC-0008.
لا تضيف dependency جديدة.

## 4. المفاهيم المستخدمة
Channel Context، Activity، Membership، Role Assignment، Sale، Offering، Product، Authorization Grant، Agent، Agent Action، Conversation، Message، Provenance، Audit Record، Device، Pending Operation، Conflict.
لا Channel Concept جديد ولا Checkout Concept.

## 5. Channel Context
Channel Context هو سياق بدء/تنفيذ التفاعل.
حالاته الدلالية القائمة:
**opened → active → closed**
عند انطباقها.
هو لا يملك العملية التي بدأت من خلاله.

Channel Context يمكن أن يصف مصدر بدء مثل:
- barcode.
- touch.
- conversation.
- voice.
- agent.
هذه طرق/سياقات بدء، وليست Sales مستقلة.

## 6. Channel Context ≠ Sale
بدء التفاعل من أي قناة لا ينشئ Sale تلقائياً.
يمكن أن يبدأ Sale من Channel Context، لكن:
**Channel Context ≠ Sale**
وSale تبقى Commerce truth وفق SPEC-0005.

إعادة فتح/إغلاق Channel Context لا تعيد كتابة Sale history.

## 7. Activity context
عند بدء Sale أو طلب متعلق بـOffering:
- Activity يحدد السياق التجاري.
- Membership/Role Assignment تصف علاقة الفاعل بالنشاط.
- Authorization تحدد الفعل المسموح.
- Channel Context يصف فقط قناة/سياق البدء.

وجود قناة لا يتجاوز Activity context.
وجود Role Assignment لا يمنح Authorization تلقائياً.

## 8. Authorization boundary
Authorization من SPEC-0003 هي صاحبة قرار السلطة.
Channel Context لا يمنح صلاحية.
Channel لا يوسع Role Assignment.
Agent لا يكتسب authority من القناة.
لا يصبح barcode/touch/conversation/voice/agent بديلاً عن Authorization.

## 9. طرق البدء
### Barcode
طريقة إدخال/بدء تشير إلى عرض/سياق محتمل؛ لا تنشئ Sale بذاتها.
### Touch
سياق تفاعل؛ لا يملك Sale.
### Conversation
قد يبدأ طلباً أو تفاعلاً تجارياً؛ Conversation لا تصبح Sale.
### Voice
طريقة تفاعل؛ لا تعني تنفيذ Sale دون السلطة اللازمة.
### Agent
يمكن أن يبدأ أو يجهز تفاعلاً إذا كان مخولاً؛ Agent لا يملك Sale.

لا تفرض المواصفة taxonomy نهائية للقنوات؛ DEC-0008 DECIDED / RESOLVED.

## 10. Lifecycle / behavior
المسار الدلالي الممكن:
**Channel Context opened → interaction → authorized action عند الحاجة → Commerce Sale behavior → Channel Context closed**
ليس كل تفاعل يؤدي إلى Sale.
Sale lifecycle يبقى في SPEC-0005.
Authorization decision يبقى في SPEC-0003.

## 11. Failure / Exception boundaries
- Channel opened ≠ Sale created.
- Channel closed ≠ Sale cancelled.
- barcode/touch/voice failure ≠ Commerce failure بالضرورة.
- Conversation failed ≠ Sale failed تلقائياً.
- Agent channel ≠ Agent authority.
- Unauthorized channel action ≠ valid Sale.
- إعادة المحاولة من قناة ≠ Sale جديدة تلقائياً.
تفاصيل التكرار/الإلغاء العابرة للمجالات تبقى في المواصفات المالكة.

## 12. History / Provenance / Audit
Channel Context history يوضح بدء/استمرار/إغلاق السياق.
Provenance يربط مصدر بدء التفاعل عند الحاجة.
Audit Record يسجل الأفعال ذات الحاجة الرقابية.
Sale history تبقى لدى Commerce.
Authorization history تبقى لدى Authorization.
لا يملك Channel Domain Truth للعمليات التي بدأت منه.

## 13. Privacy
Channel Context قد يحمل معلومات عن مصدر التفاعل أو محتواه.
الوصول يخضع Authorization والغرض والسياق.
Conversation/Voice لا يمنحان وصولاً إلى Health/Finance لمجرد كونهما قناة.
Agent لا يوسع الصلاحية عبر Channel Context.

## 14. Offline / Agent
Offline Channel Context ≠ Final Sale.
Pending Operation لا تجعل Channel Context مالكاً للحقيقة.
Agent Action عبر Channel لا تصبح Sale إلا وفق Commerce وAuthorization.
لا Sync algorithm.
