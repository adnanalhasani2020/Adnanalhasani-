# SPEC-0011 — سلطة الذكاء الاصطناعي الصحية

## 1. الغرض والنطاق
تحدد هذه المواصفة الحد الدلالي لعمل Agent في السياق الصحي وفق المفاهيم الموجودة: Agent، Authority Policy، Agent Action، Approval، Authorization Grant، Clinical Record، Prescription.
لا تنشئ AI Model أو Diagnosis أو أي Concept صحي/تقني جديد.

| REQ | Primary | Supporting | تغطية |
|---|---|---|---|
| REQ-FUNC-0026 | SPEC-0010 | SPEC-0011 | حدود عدم التشخيص الذاتي والقرار السريري |
SPEC-0011 تدعم REQ-0026 ولا تنتزع ملكيته من SPEC-0010.

## 3. Dependencies
حسب جرد Stage 6:
- SPEC-0010
- SPEC-0017
- SPEC-0018
- External: DEC-0001 وDEC-0007.
SPEC-0017 وSPEC-0018 لم تبدأهما هذه الدفعة؛ الاعتماد الدلالي محفوظ ولا يعني إنشاءهما الآن.

## 4. المفاهيم المستخدمة
Agent، Authority Policy، Agent Action، Approval، Authorization Grant، Clinical Record، Prescription، Provenance، Audit Record، Patient Context، Encounter.
لا AI Model، ولا Diagnosis، ولا مفهوم جديد.

## 5. قاعدة السلطة الصحية
**Agent ≠ Clinical Decision.**
Agent يعمل ضمن authority موجودة؛ قدرته على الاقتراح أو التنفيذ لا تمنحه سلطة إضافية.
Authorization وAuthority Policy تحددان الحدود، وApproval يستخدم عندما يفرض السياق/القرار مراجعة بشرية.

## 6. Recommendation
Recommendation هي مخرَج اقتراحي للفعل أو التقييم.
**Recommendation ≠ Prescription.**
**Recommendation ≠ Clinical Decision.**
وجود Recommendation لا يغير Clinical Record ولا Patient Context ولا Prescription.

لا تفترض المواصفة أن كل Recommendation تحتاج Approval؛ تحديد الأفعال التي تتطلبها الموافقة يبقى قراراً مفتوحاً.

## 7. Agent Action
Agent Action هو فعل أو محاولة فعل من الوكيل.
**Agent Action ≠ Approval.**
يمكن أن يكون:
**prepared → approved/rejected → executed/failed**
عندما تنطبق هذه المراحل، دون فرض lifecycle موحد لكل فعل.

Approval ليس Authority دائمة؛ وهو منفصل عن Agent Action.

## 8. Human oversight / approval
القاعدة الحالية:
- الأفعال التي يصنفها المشروع لاحقاً كحساسة يمكن إيقافها حتى المراجعة/الموافقة البشرية.
- الموافقة البشرية لا تنقل Domain Ownership إلى الشخص الموافق.
- الموافقة لا تحول Recommendation إلى Clinical Truth بذاتها.
- تفاصيل قائمة الأفعال وحدود الاستقلالية الطبية لم تُحسم.

DEC-0007 أصبح DECIDED / RESOLVED، وكذلك DEC-0001.

## 9. Clinical Truth boundary
Clinical Record وResult/Report وPrescription حقائق Health.
Agent لا يملك أياً منها.
Agent Action لا تصبح Clinical Record أو Prescription تلقائياً.
إذا نُفذ فعل مصرح به وغيّر المجال، فإن Health هو الذي يملك الحقيقة الناتجة.

## 10. Authorization / Authority Policy
Authorization Grant يحدد الصلاحية وفق السياق والنطاق والغرض والمدة عند الحاجة.
Authority Policy تحدد ما يمكن للوكيل فعله ضمن السياسة.
لا تنشئ المواصفة Permission أو AI Capability Concept جديداً.
Agent لا يوسّع Authorization بنفسه.

## 11. Lifecycle / behavior
المسار المفاهيمي:
**Observation/Retrieval → Recommendation → Preparation → Approval عند الحاجة → Execution → Provenance/Audit**
ليس كل فعل يمر بكل مرحلة.
المرحلة السابقة لا تعني تحقق المرحلة اللاحقة:
Recommendation ≠ Preparation ≠ Execution.
Approval ≠ Execution.

## 12. Failure / Exception boundaries
- Recommendation فاشلة ≠ Clinical Decision.
- Approval مرفوضة ≠ Execution.
- Agent Action failed ≠ Clinical Truth.
- Agent غير المصرح له ≠ سلطة مكتسبة.
- انتهاء Authorization ≠ استمرار صلاحية الفعل.
- فشل Agent لا يمحو Clinical History.
- Approval لا تعني أن النتيجة السريرية صحيحة تلقائياً.

## 13. History / Provenance / Audit
Provenance يوضح أصل المعلومة أو الفعل ومصدره.
Audit Record يسجل ما يلزم رقابياً.
Agent Action يحتفظ بسياقه ونتيجته الدلالية.
لا يتحول Audit أو Provenance إلى Clinical Truth.

## 14. Privacy
Health sensitive؛ الوصول إلى Clinical Truth يخضع Authorization.
Agent لا يقرأ أو يغير السجل السريري خارج السلطة الممنوحة.
لا تضيف هذه المواصفة تصنيفاً قانونياً جديداً أو قاعدة احتفاظ جديدة.

## 15. Offline
**Offline Agent Action ≠ Clinical Finality.**
Pending Operation على Device لا تصبح Clinical Truth.
Conflict يعود إلى Owner Domain الصحي.
لا Sync algorithm.
