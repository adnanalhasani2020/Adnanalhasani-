# SPEC-0009 — الأثر المالي والدفتر والرصيد

## 1. الغرض والنطاق
تحدد هذه المواصفة حدود Financial Transaction وLedger Entry وBalance باعتبارها الحقيقة المالية المعترف بها ومشتقاتها، مع ربطها دلالياً بـInvoice وObligation وPayment وSettlement وSale.
القاعدة:
**Financial Transaction → Finance**
**Ledger Entry → Finance / source of truth after recognition**
**Balance → derived**
بينما:
**Invoice → Commerce truth**
**Payment/Settlement → operational/payment truth**.
لا تنشئ Account Balance ككيان جديد ولا تفرض Event Sourcing أو تقنية مماثلة.

## 4. المفاهيم المستخدمة
Financial Transaction، Ledger Entry، Balance، Financial Account، Invoice، Sale، Obligation، Payment، Settlement، Provenance، Audit Record، Domain History، State Record، Pending Operation، Conflict.
لا تضيف Account Balance أو Event أو Event Sourcing كـConcepts.

## 5. Financial Transaction
Financial Transaction هي واقعة/حركة مالية معترف بها في Finance.
ليست اسماً جامعاً لـPayment أو Settlement.
قد تمر دلالياً بـ:
**initiated → pending → completed/failed → reversed/cancelled**
عند انطباق المعنى.
وجود Payment أو Settlement لا ينقل الملكية إلى Payments إذا أصبحت الواقعة Financial Truth.

## 6. Recognition boundary
عندما يصبح أثر مالي معترفاً به:
- Finance يملك Financial Transaction.
- Finance يملك Ledger Entry.
- Balance يشتق من الحقيقة المالية المعترف بها.
قبل الاعتراف:
- قد توجد حالة تشغيلية أو Pending Operation.
- لا تصبح Pending Operation Domain Truth نهائية.
هذه المواصفة لا تحدد قاعدة تقنية أو محاسبية لتنفيذ الاعتراف.

## 7. Ledger Entry
Ledger Entry هو الأثر المالي المعترف به ضمن Financial Account والسياق المالي.
يمكن أن يمر قبل النشر بحالة proposed/pending، ثم posted، ثم reversed/adjusted/corrected عند انطباق المعنى.

### 7.1 التاريخ
بعد دخول القيد في التاريخ المالي المعترف به:
- لا يحذف لإخفاء خطأ.
- Reversal يفسر انعكاس الأثر.
- Correction يفسر التصحيح.
- Provenance/Audit يبقيان منفصلين عن القيد نفسه.
لا تفرض المواصفة شكلاً محاسبياً أو Event Sourcing.

## 8. Balance
Balance هو قراءة مشتقة من Financial Account وLedger Entries والسياق والزمن.
يمكن أن تكون القراءة as-of وقت معين.
Balance ليس سجل حركة.
لا يعدل كحقيقة مستقلة.
لا ينشأ Ledger Entry من Balance.
لا ننشئ Account Balance كـConcept جديد.

### 8.1 pending
قد تعرض قراءة مشتقة آثاراً معلقة إذا كان ذلك جزءاً من تعريف القراءة، لكن يجب تمييزها عن الحقيقة المالية المعترف بها.
Pending projection ≠ Ledger Truth.

## 9. Invoice
Invoice هي Commerce truth للوثيقة وحالتها التجارية.
قد تكون أساساً أو مرجعاً لأثر مالي معترف به، لكن:
**Invoice ≠ Financial Transaction**
**Invoice ≠ Ledger Entry**
Commerce لا يملك Ledger بسبب إنشاء Invoice.

## 10. Sale
Sale هي Commerce truth.
يمكن أن ينتج عنها Invoice/Obligation، ثم Payment/Settlement، ثم أثر مالي معترف به.
هذا مسار مرجعي وليس سلسلة إلزامية.
Sale لا تصبح Financial Transaction لمجرد وجود أثر مالي مرتبط بها.

## 11. Obligation
Obligation تملكها Financial Relations.
قد تنشأ من Sale/Invoice/Loan.
Payment/Settlement قد تعالجها.
Ledger Entry يمثل الأثر المالي المعترف به، ولا يصبح Obligation نفسها.

## 12. Payment / Settlement
Payment تملكها Payments.
Settlement تملكها Payments/Settlement.
إذا نتج عن أي منهما أثر مالي معترف به:
**Financial recognition → Finance**.
لا يصبح Payment أو Settlement Ledger Entry تلقائياً.

## 13. العلاقة المرجعية
المسار:
**Sale → Invoice → Obligation → Payment → Settlement → Financial Transaction → Ledger Entry → Balance**
مفيد للفهم لكنه غير إلزامي.
Loan قد يولد Obligation دون Invoice.
Obligation قد توجد دون Payment.
Payment قد تفشل أو تبقى pending.
Settlement قد تكون منفصلة عن Payment.
Balance دائماً مشتق.

## 14. Correction / Reversal / History
Correction لا تعني إعادة كتابة الماضي بصمت.
Reversal لا يعني حذف الأصل.
تعديل Invoice أو Obligation لا يمحو Financial Transaction المعترف بها دون قاعدة مالية صريحة.
History يظل قابلاً للتفسير.
Provenance يصف الأصل/الاشتقاق.
Audit Record يسجل الفعل/القرار.
لا تفرض هذه المواصفة Event Sourcing.

## 15. Failure / Exception boundaries
- Invoice issued ≠ Ledger posted.
- Payment completed ≠ Ledger finality بالضرورة.
- Settlement settled ≠ Ledger Entry في كل سياق.
- Financial Transaction failed ≠ حذف التاريخ.
- Reversal ≠ حذف الأصل.
- Balance stale ≠ تغيير Source of Truth.
- Conflict ≠ Finance truth جديدة.
- Offline ≠ Financial finality.

## 16. Privacy / Authorization
الوصول إلى Financial Account/Ledger/Balance يخضع Authorization.
وجود Financial Account لا يمنح Access Account صلاحية.
Role/Family/Agent لا يمنح وصولاً مالياً تلقائياً.
لا تملك هذه المواصفة Authorization.

## 17. Offline / Agent
Pending Operation وDevice وConflict ليست Source of Truth مالي.
Agent لا يملك Financial Transaction أو Ledger Entry أو Balance.
Agent Action قد يطلب أو يسبب فعلاً مصرحاً، لكن Owner Domain يملك الحقيقة بعد الاعتراف.
لا تحدد Sync algorithm.
