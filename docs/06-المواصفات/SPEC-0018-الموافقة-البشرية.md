# SPEC-0018 — الموافقة البشرية

## 1. الغرض والنطاق
تحدد هذه المواصفة المعنى الدلالي لـApproval البشرية في سياق أفعال Agent، وحدودها مع Agent Action وAuthority Policy وAuthorization وDomain Ownership.
لا تنشئ Consent أو Human Approver كـConcept جديد، ولا تحول الموافقة إلى UI أو workflow تقني.

| REQ | Primary | Supporting | التغطية |

| REQ-FUNC-0045 | SPEC-0018 | — | إمكانية إيقاف فعل Agent لطلب موافقة بشرية عندما يحدد المشروع أن الفعل يحتاجها |
لا تغيّر هذه المواصفة Primary/Supporting ownership.

## 3. Dependencies
- SPEC-0017: Agent Action وحدود سلطة الوكيل.
- Domain Constraint: Authorization/Authority Policy تحددان السلطة ضمن السياق.
- External: DEC-0006 وDEC-0007.
لا تنشئ هذه المواصفة Dependency على UI أو نظام سير عمل.

## 4. المفاهيم المستخدمة
Approval، Agent Action، Authority Policy، Authorization Grant، Agent، Person، Provenance، Audit Record، Domain Truth.
لا Consent Concept ولا Human Approver Concept جديد.

## 5. Approval
Approval هي فعل/قرار حوكمي يدل على قبول أو رفض أو مراجعة فعل محدد عندما تكون الموافقة مطلوبة.
**Approval ≠ Agent Action.**
الموافقة لا تعني أن الفعل قد نُفذ؛ كما أن رفضها لا يمحو تاريخ الطلب أو الفعل المجهز.

## 6. Authority boundary
الموافقة البشرية تعتمد حدودياً على Authority Policy وAuthorization القائمة:
- وجود موافقة لا ينشئ Authorization من الصفر خارج القواعد المسموح بها.
- وجود Authorization لا يعني أن Approval مطلوبة لكل فعل.
- تحديد الأفعال التي تتطلب Approval يبقى قراراً مفتوحاً.
- Approval لا تمنح الشخص الموافق ملكية Domain Truth.

لا تفترض المواصفة صفة قانونية محددة للشخص الموافق.

## 7. العلاقة مع Agent Action
يمكن أن تكون Approval مرتبطة بـAgent Action في سياق يتطلب مراجعة بشرية.
المسار الدلالي الممكن:
**prepared → approval requested → approved/rejected → executed/failed**
ولا يعني ذلك أن كل Agent Action يمر بهذه المراحل.

**Approval ≠ Execution.**
**Approval ≠ Domain Truth.**

## 8. Failure / Exception boundaries
- Approval rejected ≠ Execution.
- Approval pending ≠ Domain Finality.
- Approval expired/invalid حيث ينطبق ≠ استمرار الصلاحية.
- Agent Action failed ≠ Approval.
- Approval لا تصحح Domain Truth تلقائياً.
- وجود Approval لا ينقل Domain Ownership.
- فقدان الجهاز الذي يحمل حالة محلية للموافقة لا يثبت نهائية القرار.

## 9. History / Provenance / Audit
Approval نفسها تحتاج تتبعاً دلالياً عند الحاجة:
- من قام بالفعل ضمن السياق المسموح.
- ما الفعل المرتبط.
- متى.
- النتيجة.
Provenance يصف الأصل/السياق، وAudit Record يسجل ما يلزم للتدقيق.
**Approval ≠ Provenance ≠ Audit Record ≠ Domain Truth.**
لا تفرض المواصفة Event Sourcing.

## 10. Privacy / Authorization
الموافقة على فعل حساس لا تفتح وصولاً عاماً إلى البيانات.
الوصول يظل محكوماً بـAuthorization والغرض والسياق.
لا تستخدم Family Relationship أو Role Assignment كبديل تلقائي عن Authorization.
Agent لا يوسّع الصلاحية عبر طلب Approval.

## 11. Offline / Device
**Offline Approval ≠ Finality.**
Pending Operation لا تصبح Domain Truth لمجرد وجود Approval محلية.
Device ≠ Source of Truth.
إذا احتاجت الموافقة إلى اعتراف Owner Domain أو Authority Domain، فذلك الاعتراف هو الحد الذي يحدد النهائية وفق السياسة المقررة.
