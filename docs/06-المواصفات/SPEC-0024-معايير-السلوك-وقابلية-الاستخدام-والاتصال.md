# SPEC-0024 — معايير السلوك وقابلية الاستخدام والاتصال

## 1. الغرض والنطاق
تحدد هذه المواصفة NFR/Acceptance semantics فقط للسلوك المتوقع عند الاستخدام العادي وضعف الاتصال والعمل دون اتصال، مع قابلية السلوك للتوقع والفهم.
لا تحول المعايير إلى UI specification أو performance engineering أو protocol.

## 4. نطاق NFR
السلوك المطلوب دلالياً:
- مفهوم وقابل للتوقع.
- يميز local/pending/final عند انطباقها.
- لا يضلل بشأن النجاح أو الفشل أو النهائية.
- متسق مع Owner Domain boundaries.
هذه أوصاف قبول وسلوك وليست مواصفات واجهة.

## 5. Usability semantics
قابلية الاستخدام تعني أن المستخدم يستطيع فهم الحالة ذات الصلة دون استنتاج مضلل، خصوصاً الفرق بين pending/completed، rejected/failed عندما يميزهما المجال، local/final، conflict/resolved، cancelled/reversed.
لا تحدد المواصفة شاشة أو زر أو تصميم تفاعل.

## 6. Weak connectivity
عند ضعف الاتصال لا يُعرض نجاح محلي على أنه Domain Finality.
يمكن أن تبقى العملية Pending، ويجب أن يكون الفرق بين الانقطاع والعملية المعلقة والحالة النهائية مفهوماً سلوكياً.
استعادة الاتصال لا تعني تلقائياً نجاح العملية أو فشلها؛ Owner Domain يحدد الحالة.
لا retry protocol أو timeout أو transport behavior.

## 7. Predictable behavior
- الحالة الدومينية لا تفسر بمعانٍ متناقضة بلا سبب مجالّي.
- انتقال Pending إلى Final/Rejected/Cancelled يخضع لمعنى Owner Domain.
- التكرار لا يعامل كأثر جديد تلقائياً.
- Conflict لا يختفي بقرار صامت غير معتمد.
- Agent لا يغير finality خارج سلطته.

## 8. Offline boundary
**Offline ≠ Finality.**
Pending Operation ليست Domain Truth.
Device ليس Source of Truth.
Health/Finance/Commerce لا تحصل على finality لمجرد العمل offline.
لا تحدد المواصفة الأعمال المالية المسموحة offline.

## 9. Acceptance semantics
- AC-01 تمييز local/pending/final.
- AC-02 weak connectivity لا تنتج finality تلقائياً.
- AC-03 حالات الرفض/الفشل/الإلغاء/العكس لا تخلط دلالياً.
- AC-04 conflict يبقى معلناً حتى يقرر Owner Domain.
- AC-05 القبول لا يفرض UI/Protocol.
- AC-06 لا أرقام أداء أو SLA غير معتمدة.

## 10. Failure / History / Privacy
Network weakness ≠ Domain failure.
Offline ≠ Finality.
Pending ≠ Failure تلقائياً.
Local success ≠ Domain success.
Reconnection ≠ automatic completion.
Conflict ≠ resolved.
NFR لا تملك Domain History، وتبقى Provenance/Audit/History عند ملاكها.
Usability لا تتجاوز Authorization أو Privacy.

## 11. Source of Truth
| الحقيقة | المالك |
|---|---|
| Domain Truth | Owner Domain |
| Pending/State representation | المفهوم التشغيلي القائم |
| Authorization | Authorization |
| Provenance/Audit | وفق المفهوم المالك |
| NFR acceptance | Cross-cutting؛ لا يملك Domain Truth |
