# SPEC-0017 — سلطة الوكيل والفعل المفوض

## 1. الغرض والنطاق
تحدد هذه المواصفة الحدود الدلالية لسلطة Agent والفعل الذي ينفذه أو يجهزه، مع الفصل بين Agent وPerson وDomain Owner وAuthorization Grant وAuthority Policy وApproval.
لا تنشئ Autonomous Authority جديدة، ولا تمنح Agent سلطة من قدرته التقنية على التنفيذ.

## 2. REQ Traceability والملكية
| REQ | Primary | Supporting | التغطية |
|---|---|---|---|
| REQ-FUNC-0042 | SPEC-0017 | SPEC-0003 | عمل Agent ضمن الصلاحية دون اكتساب سلطة إضافية |
| REQ-FUNC-0043 | SPEC-0017 | SPEC-0018 | فصل Recommendation/Preparation عن Execution |
| REQ-SEC-0044 | SPEC-0017 | — | تتبع من فوّض Agent والفعل والسياق والنتيجة |
لا تغيّر هذه المواصفة Primary/Supporting ownership.

## 3. Dependencies
- SPEC-0003: Authorization وAuthority boundary.
- Domain Constraint: Owner Domain retains Domain Truth.
- External: DEC-0006 وDEC-0007.
لا تنشئ Dependency على SPEC-0018؛ مواصفة الموافقة تعتمد عليها، بينما هذا الملف يعرّف حد Agent Action دون تحويل Approval إلى شرط عالمي.

## 4. المفاهيم المستخدمة
Agent، Person، Authority Policy، Authorization Grant، Agent Action، Recommendation، Approval، Provenance، Audit Record، Domain Truth، Device، Pending Operation.
لا Autonomous Authority Concept جديد.

## 5. Agent boundary
**Agent ≠ Person.**
**Agent ≠ Domain Owner.**
Agent هو فاعل تشغيلي/وكيل ضمن السلطة الممنوحة له. لا يصبح Person لمجرد ارتباطه بشخص، ولا يصبح مالكاً للحقيقة التي يعمل عليها.

القدرة التقنية على قراءة أو تنفيذ فعل لا تثبت وجود Authorization.

## 6. Authority Policy وAuthorization Grant
**Authority Policy ≠ Authorization Grant.**
Authority Policy تحدد إطار/حدود ما يمكن للوكيل فعله في سياق معين.
Authorization Grant تمنح سلطة محددة وفق السياق والغرض والنطاق والمدة عند انطباقها.
Agent لا ينشئ أو يوسع Authorization لنفسه.
Role أو Channel أو Agent capability لا تُستعمل كبديل عن Authorization.

## 7. Agent Action
Agent Action هو فعل أو محاولة فعل من Agent، ويحمل دلالياً عند الحاجة:
- الفاعل/الوكيل.
- مصدر السلطة.
- الهدف أو المجال المتأثر.
- الزمن/السياق.
- النتيجة.
يمكن أن يمر عبر:
**prepared → approved/rejected عند الحاجة → executed/failed**
ولا يلزم هذا المسار لكل فعل.

**Agent Action ≠ Approval.**

## 8. Recommendation وExecution
**Recommendation ≠ Execution.**
Recommendation اقتراح أو مخرج قابل للمراجعة، ولا يغيّر Domain Truth بذاته.
Preparation تجهيز قابل للتنفيذ عند انطباقه، ولا يساوي Execution.
Execution لا تكون مشروعة لمجرد وجود Recommendation؛ يلزمها authority المناسبة.

## 9. Autonomous authority
لا تنشئ هذه المواصفة أي Autonomous Authority جديدة.
إذا لم توجد Authorization/Policy تسمح بالفعل، فلا يستمد Agent السلطة من:
- قدرته التقنية.
- نجاح أفعال سابقة.
- كونه متصلاً بقناة.
- ارتباطه بشخص.
- كونه قادراً على إنشاء/تعديل Pending Operation.
DEC-0006 وDEC-0007 هما حدود القرار الخاصة بالأفعال المالية والصحية.

## 10. Lifecycle / behavior
المسار الدلالي الممكن:
**Observation → Retrieval → Recommendation → Preparation → Execution → Provenance/Audit**
مع Approval/Review عند الحاجة.
الانتقال بين المراحل لا يفترض أن المرحلة السابقة تحقق اللاحقة.
Execution قد يغيّر Domain Truth فقط عندما يكون الفعل مصرحاً به ويقبله Owner Domain.

## 11. Failure / Exception boundaries
- Agent غير المصرح له ≠ سلطة مكتسبة.
- Recommendation فاشلة ≠ Execution.
- Preparation ≠ Execution.
- Approval مرفوضة ≠ Execution.
- Agent Action failed ≠ Domain Truth.
- Pending Agent Action ≠ Domain Truth.
- انتهاء/سحب Authorization يمنع استمرار السلطة وفق حدودها.
- Agent Action عبر جهاز مفقود لا يمحو Domain History.

## 12. Domain Truth / Ownership
إذا نفذ Agent فعلاً مصرحاً به:
- المجال المستهدف يملك الحقيقة الناتجة.
- Agent يملك فقط دلالة الفعل التشغيلي وسياقه ضمن حدود النموذج.
- Provenance يصف أصل/مسار الفعل.
- Audit Record يسجل ما يلزم للتدقيق.
**Agent لا يصبح Source of Truth للمجال.**

## 13. History / Provenance / Audit
Agent Action history منفصل عن Domain History.
Provenance يصف مصدر/اشتقاق المعلومة أو الفعل.
Audit Record يسجل الفعل أو الوصول أو القرار لأغراض التدقيق.
**Provenance/Audit ≠ Domain Truth.**
لا تعتمد هذه المواصفة Event Sourcing.

## 14. Authorization / Privacy
الأفعال الحساسة تخضع Authorization وPurpose/Context بحسب المجال.
Agent لا يقرأ أو يغير بيانات خارج السلطة الممنوحة.
لا تفترض المواصفة أن Role أو Family Relationship يمنح Agent وصولاً تلقائياً.
لا تضيف taxonomy قانونية أو سياسة احتفاظ جديدة.

## 15. Offline / Device
**Offline Agent Action ≠ Domain Finality.**
Pending Operation على Device لا تصبح Domain Truth.
Device ليس Source of Truth.
إذا وقع تعارض، يعود الحسم إلى Owner Domain؛ لا يملك Agent التعارض ولا يقرر الحقيقة الدومينية من تلقاء نفسه.
لا Sync/Conflict algorithm.

## 16. Source of Truth
| الحقيقة | المالك |
|---|---|

| Authorization Grant | Authorization |
| Authority Policy | Authorization/Governance ضمن المفهوم القائم |
| Domain Truth | Owner Domain |
| Agent Action | Agent/Governance ضمن حدوده |
| Provenance | المجال الذي تصف حقيقته |
| Audit Record | Audit |
| Device/Pending Operation | تشغيلي وليس Domain Truth |
