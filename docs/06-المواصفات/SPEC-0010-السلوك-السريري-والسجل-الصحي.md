# SPEC-0010 — السلوك السريري والسجل الصحي

## 1. الغرض والنطاق
تحدد هذه المواصفة السلوك الدلالي للصحة والسجل السريري وحدود Patient Context وEncounter وClinical Record وResult/Report وPrescription، مع الفصل الصريح عن الهوية والمال والوكيل والاتصال.
لا تنشئ Diagnosis أو AI Model أو مفاهيم صحية جديدة، ولا تحدد DB أو API أو UI أو معيار تنفيذ.

- SPEC-0003: Authorization والسياق الوصولي.

لا تُنشئ المواصفة dependency جديدة.

## 4. المفاهيم المستخدمة
Person، Patient Context، Encounter، Clinical Record، Result/Report، Prescription، Service، Activity، Financial Reference، Authorization Grant، Agent، Authority Policy، Approval، Agent Action، Provenance، Audit Record، Device، Pending Operation، Conflict، State Record.
لا Concept جديد.

## 5. Patient Context
Patient Context هو سياق الشخص كمستفيد صحي، وليس هوية جديدة.
**Patient Context ≠ Person identity.**
- Person → Identity.
- Patient Context → Health.
- Access Account مستقل.
- Family Relationship لا تمنح وصولاً تلقائياً.
- Authorization/Delegation تحدد الوصول أو الفعل ضمن النطاق.

إنهاء Patient Context لا يمحو التاريخ الصحي ولا ينشئ Person جديداً.

## 6. Encounter
Encounter هو تفاعل رعاية محدد داخل Patient Context.
دورة محتملة:
**planned → in-progress → completed / cancelled**
ولا تستخدم حالة إضافية إلا إذا كان لها معنى مستقل.

Encounter قد يرتبط بـService وActivity وClinical Records وResult/Report وPrescription.
**Encounter ≠ Invoice.**
**Encounter ≠ Payment.**
قد ينتج Financial Reference، لكنه لا يملك الحقيقة المالية.

## 7. Clinical Record
Clinical Record هو معلومة سريرية موثقة.
**Clinical Record = clinical truth** ضمن نطاق Health.
الحالات القائمة عند الحاجة:
**draft → recorded → amended / corrected / invalidated**
ولا تفرض كل الحالات على كل سجل.

التصحيح لا يمحو التاريخ. Communication أو Finance أو Agent لا يصبح مالكاً للسجل لمجرد قراءته أو الإشارة إليه.

## 8. Result / Report
Result/Report هو نتيجة أو تقرير صحي ذو معنى مستقل، وليس مجرد مرفق.
قد يرتبط بـPatient Context وEncounter وClinical Record.
يمكن أن يمر بـ:
**preliminary → final → amended / corrected**
عند انطباق المعنى.

**Result/Report ≠ Clinical Record**، وإن أمكن الربط بينهما.
التوقيت الفعلي/الأداء منفصل دلالياً عن وقت الإصدار أو التعديل.

## 9. Prescription
Prescription هو توجيه/طلب علاجي معترف به في السياق السريري.
**Prescription ≠ Recommendation.**
**Prescription ≠ Clinical Decision.**
ولا يعني وجود Recommendation أن Prescription صدرت.

يمكن أن تمر Prescription بحالات:
**draft → issued → active → amended / cancelled / expired / fulfilled**
بحسب السياق.

لا تنشئ هذه المواصفة Medication أو Diagnosis أو Dispensing Concept.

## 10. Clinical Decision والوكيل
Clinical Decision ليست ملكية Agent.
المسار المفاهيمي:
**Clinical Information → Recommendation → Approval/Decision عند الحاجة → Action**
والتفصيل النهائي لحدود استقلالية AI يبقى في SPEC-0011 والقرارات المفتوحة.

Agent لا يملك Clinical Truth.
Agent Action لا تصبح Clinical Record أو Prescription تلقائياً.
Recommendation لا تصبح Decision لمجرد إنتاجها بواسطة Agent.

## 11. Health ≠ Finance
Health يملك:
- Patient Context.
- Encounter.
- Clinical Record.
- Result/Report.
- Prescription.

Finance/Commerce يملكان الحقائق المالية والتجارية وفق حدودها.
Financial Reference رابط سياقي فقط.

**Encounter ≠ Invoice/Payment.**
**Clinical Record ≠ Financial Transaction/Ledger Entry.**
الخدمة الصحية قد تكون مجانية أو قد ترتبط بمسار مالي، دون دمج الملكية.

## 12. Authorization / Privacy
الصحة شديدة الحساسية.
Family Relationship أو Role Assignment لا تمنح وصولاً صحياً تلقائياً.
Authorization Grant وDelegation تحددان الوصول أو الفعل وفق السياق والغرض والنطاق.
Authorization لا تنقل ملكية Clinical Truth.
Agent لا يوسّع صلاحية نفسه.

لا تضيف المواصفة taxonomy قانونية أو قاعدة ولاية قضائية عامة؛ DEC-0001 وDEC-0010 يبقيان DECIDED / RESOLVED.

## 13. Failure / Exception boundaries
- Patient Context منتهٍ ≠ حذف التاريخ.
- Encounter cancelled ≠ حذف Clinical Record التاريخي عند وجوده.
- Result preliminary ≠ final بالضرورة.
- Prescription cancelled ≠ محو تاريخها.
- Recommendation ≠ Prescription.
- Agent Action failed ≠ Clinical Truth جديدة.
- Invoice/Payment failure ≠ Clinical failure تلقائياً.
- Financial linkage failure لا ينقل السجل السريري إلى Finance.

## 14. History / Provenance / Audit
Clinical History منفصل عن Current State.
Provenance يصف أصل/إنشاء/تعديل المعلومة.
Audit Record يسجل الفعل/الوصول/التغيير لأغراض التدقيق.
**Provenance ≠ Audit ≠ Clinical Record.**
Correction/Amendment لا يساوي Delete History.

## 15. Offline / Conflict
**Offline ≠ Final Clinical Truth.**
Device وPending Operation لا يملكان الحقيقة الصحية.
Conflict لا ينشئ Clinical Truth ثانية.
عند تعارض السجل الصحي، يبقى Owner Domain الصحي صاحب الحقيقة؛ REQ-0066 وقرار الحسم التفصيلي من نطاق SPEC-0020.
لا تحدد المواصفة Sync/Conflict algorithm.

## 16. Agent boundary
Agent يمكنه Observation/Retrieval/Recommendation/Preparation أو Execution فقط ضمن Authority/Authorization القائمة.
لا يصبح Agent:
- Patient Context.
- Clinical Record owner.
- Prescription owner.
- Clinical Decision owner.
لا يكتسب authority من قدرته التقنية.

| Person | Identity |
| Patient Context | Health |
| Encounter | Health |
| Clinical Record | Health |

| Prescription | Health |
