# خريطة Stage 6 — المواصفات

## 1. تعريف المرحلة
المواصفات في هذا المشروع هي طبقة **سلوكية ودلالية** بين المتطلبات/القيود والنموذج المفاهيمي من جهة والتنفيذ والاختبار من جهة أخرى.

المواصفة تحدد ما يجب أن يحدث، تحت أي شروط، وما الذي يُسمح به أو يُمنع، وكيف تتغير الحالة، وما النتيجة المتوقعة، وكيف يمكن التحقق منها لاحقاً.

**ليست** تحويل نموذج البيانات إلى جداول، وليست قراراً تقنياً للتخزين أو API أو UI أو المزامنة أو الذكاء الاصطناعي أو المدفوعات.

## 2. أساس المرحلة
- Stage 5 مغلقة رسمياً.
- المرجع المفاهيمي: `ed8a8f14ffd3f28061e788db1cd8c5a5e9bed1ad`.
- 47 Domain Concepts + State Record Modeling Construct.
- 57 Canonical Relationships.
- 59/59 Requirements Traceability.
- DEC-0001..DEC-0013 مفتوحة.

## 3. هدف Stage 6
تحويل ما ثبت في المتطلبات والمعمارية ونموذج البيانات والأدلة/القرارات المعتمدة إلى مواصفات سلوكية قابلة للتنفيذ والاختبار لاحقاً، مع إبقاء مناطق عدم الحسم معلنة.

## 4. أنواع المواصفات المتوقعة
القائمة الأولية المبنية على جرد الوثائق، وليست حكماً بأن كل نوع سيصبح وثيقة مستقلة:
1. Domain / Behavior Specifications.
2. Business Rules / Invariants.
3. State / Lifecycle Specifications.
4. Permission / Authorization Specifications.
5. Financial Rules.
6. Health Rules.
7. Family / Delegation / Authorization Rules.
8. Agent Authority / Approval Specifications.
9. Offline / Pending / Conflict / Multi-device Specifications.
10. Audit / Provenance / History / Privacy Specifications.
11. Exception / Failure / Recovery Specifications.
12. Non-functional behavioral/acceptance specifications.
13. Traceability Specifications.
14. Cross-domain Flow Specifications عند الحاجة.

## 5. ما يدخل
- Trigger, Preconditions, Behavior, Outcomes.
- Invariants وقواعد المجال.
- الحالات والانتقالات وشروطها.
- حدود السلطة والتفويض والموافقة.
- الفشل والاستثناءات والتكرار والإلغاء والتصحيح.
- معايير القبول السلوكية.
- الربط بالمتطلب والمفهوم والحد المعماري ومصدر الحقيقة.
- صياغات مشروطة عندما يتوقف السلوك على DEC مفتوح.

## 6. ما لا يدخل
- Code أو Implementation.
- Schema/SQL/ORM/DBMS.
- API نهائي أو UI.
- Sync Protocol أو CRDT/OT/Replication.
- AI implementation.
- Payments implementation.
- أي تعديل على Domain Concepts أو Canonical Relationships في Stage 5.
- أي Proposal/Hypothesis/Research Finding بوصفه Decision.

## 7. قالب المواصفة
لكل SPEC عند الحاجة:
**Purpose → Scope → Actors/Authority → Trigger → Preconditions → Main Behavior → Business Rules/Invariants → State/Lifecycle Effects → Outcomes → Failure/Exception → Audit/Provenance → Acceptance Criteria → Traceability → Open Decisions/Dependencies.**

ليس كل حقل إلزامياً لكل SPEC؛ يستخدم ما ينطبق فقط.

## 8. قاعدة الحسم
- ما هو ثابت ومسنود يُصاغ كقاعدة واضحة.
- ما هو مشروط يُصاغ بشرط صريح.
- ما يحتاج DEC يبقى Decision-Dependent.
- ما يحتاج بحثاً لا يُقدَّم كحقيقة أو قرار.
- لا ترفع حالة الوثيقة أو المواصفة إلى «معتمد» لمجرد إنشائها.

## 9. علاقة المرحلة بالسلسلة
**REQ → ADR/Research/Decision Context → Data Model → SPEC → Implementation → Review → Test → Achievement**
