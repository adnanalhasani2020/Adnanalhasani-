# SPEC-0013 — التواصل والرسائل والإشعارات

## 1. الغرض والنطاق
تحدد هذه المواصفة السلوك الدلالي لـConversation وMessage وChannel Context والحد السلوكي للإشعارات، مع ربط التواصل بسياق النشاط والعمليات دون نقل Domain Truth إلى Communication.
القواعد:
**Conversation ≠ Message**
**Channel Context ≠ Conversation**
**Notification ≠ Decision**
Authorization من SPEC-0003.
لا تنشئ هذه المواصفة Notification كـConcept مستقل؛ تستخدم "الإشعار" سلوكياً فقط وفق ما هو موجود في Stage 5.

## 4. المفاهيم المستخدمة
Conversation، Message، Channel Context، Person، Activity، Membership، Role Assignment، Authorization Grant، Sale، Invoice، Payment، Health/other domain references، Provenance، Audit Record، Agent.
لا تضيف Notification Concept جديداً.

## 5. Conversation
Conversation هي سياق تواصل يجمع Messages ضمن معنى تواصلي.
حالاتها القائمة:
**opened → active → closed → archived**
عند انطباقها.
Conversation ليست Message، ولا Sale، ولا Payment، ولا Authorization.

### 5.1 المشاركون والسياق
يمكن أن تضم Conversation مشاركين بحسب العلاقة/السياق المسموح.
وجود Person في Conversation لا يثبت أنه مخول بكل Domain Data المشار إليها في الرسائل.

## 6. Message
Message هي وحدة تواصل داخل Conversation.
يمكن أن تمر:
**composed → sent → delivered → read**
أو **failed** عند انطباق المعنى.
Message ليست Transaction ولا Domain State.
قد تشير إلى Domain Reference دون أن تملك الحقيقة التي تشير إليها.

## 7. Channel Context ≠ Conversation
Channel Context هو سياق بدء/تنفيذ التفاعل.
قد يبدأ منه تواصل، لكنه ليس Conversation تلقائياً.
القناة لا تملك Message أو Conversation لمجرد كونها وسيلة بدء.
Channel Context يظل مملوكاً لـChannel، وفق حدود SPEC-0015 والجرد.

## 8. ربط التواصل بالسياق
يمكن ربط Message أو Conversation بسياق عملية/علاقة عند الحاجة:
- Sale.
- Invoice.
- Payment.
- Service/other domain reference.
هذا الربط لا ينقل Source of Truth.
رسالة عن Payment لا تجعل Communication مالك Payment.
رسالة عن Health لا تجعل Communication مالك Clinical Record.

## 9. المرسل والسياق
يجب أن يكون واضحاً من أرسل Message وبأي صفة/سياق متاح.
إذا كان Person عضواً في أكثر من Activity:
- لا يكفي Person وحده لإثبات Activity context.
- Membership/Role Assignment قد يصف السياق.
- Authorization يحدد ما إذا كان الفعل مسموحاً.
- لا تمنح Message أو Conversation صلاحية جديدة.

## 10. Authorization boundary
Authorization من SPEC-0003 هي صاحب قرار السلطة.
Conversation لا تمنح access.
Message لا تمنح access.
Channel Context لا يمنح access.
Agent لا يكتسب authority من إرسال رسالة.
لا تفسر هذه المواصفة Role Assignment كAuthorization.

## 11. Notification كسلوك
الإشعار هو إخطار/تنبيه للمستهلك عن حالة أو حدث أو طلب مراجعة.
لا يعامل كـConcept جديد مستقل.
ولا يعامل كدليل نهائي على الحالة المصدر.

أمثلة:
- إشعار Payment pending لا يعني Payment settled.
- إشعار Sale confirmed لا ينشئ Ledger Entry.
- إشعار Health update لا يغير Clinical Record.
- إشعار Authorization لا يمنح Authorization بذاته.

## 12. Notification ≠ Decision
Decision يملكه المجال الذي اتخذ القرار.
Communication يعرض أو ينقل notification عن القرار.
إذا كان الإشعار يشير إلى حالة "pending"، تبقى الحقيقة pending لدى Owner Domain.
إذا وصل الإشعار متأخراً أو فشل، لا تتغير الحقيقة المصدرية بسبب ذلك.

## 13. حالات الإرسال والتسليم
يمكن أن تكون Message sent أو delivered أو read أو failed.
هذه حالات Communication وليست إثباتاً بأن Domain action حدث.
Delivery success ≠ Domain success.
Read ≠ Approval.
Message sent ≠ Payment completed.

## 14. Failure / Exception boundaries
- فشل إرسال Message لا يلغي Domain event الذي طلب الإخطار.
- تكرار Message لا يعني تكرار Sale/Payment.
- وصول Message متأخراً لا يعيد كتابة الحالة الحالية.
- رسالة قديمة لا تصبح Source of Truth.
- فشل Notification لا يساوي فشل القرار المصدر.
- Message عن عملية فاشلة لا يحولها إلى ناجحة.
تفاصيل التكرار العابر للمجالات لا تتحول هنا إلى algorithm.

## 15. History / Provenance / Audit
Communication يحتفظ بتاريخ الرسائل وحالاتها وفق معناه.
Provenance يصف الأصل أو المصدر عند الحاجة.
Audit Record يسجل الفعل/الوصول/القرار لأغراض التدقيق.
لا يصبح Message أو Notification Domain History للمجال المصدر.
Correction لا يعني حذف التاريخ.

## 16. Privacy
محتوى Conversation وMessage قد يكون حساساً.
الوصول يخضع Authorization والسياق والغرض.
لا تمنح Conversation وصولاً إلى بيانات Health/Finance/Family/Commerce لمجرد وجود مرجع إليها.
لا تضع هذه المواصفة تصنيفاً قانونياً جديداً.

## 17. Offline / Agent
Offline Message لا يثبت تسليم Domain action.
Pending Operation لا تصبح Conversation truth نهائية لمجرد وجودها على Device.
Agent يمكنه إرسال Message إذا كان مخولاً، لكنه لا يملك Domain Truth للموضوع الذي يذكره.
Agent لا يقرر authorization عبر Message.

## 18. Source of Truth
| الحقيقة | المالك |
|---|---|
| Conversation | Communication |
| Message | Communication |
| Channel Context | Channel |
| Activity/Membership/Role Assignment | Activities |
| Authorization Decision/Grant | Authorization |
| Sale/Invoice | Commerce |
| Payment/Settlement | Payments/Settlement |
| Financial Transaction/Ledger | Finance |
| Health truth | Health |
| Provenance | المجال الذي تصف حقيقته |
| Audit Record | Audit |

## 19. Invariants
1. Conversation ≠ Message.
2. Channel Context ≠ Conversation.
3. Message ≠ Transaction.
4. Notification ≠ Decision.
5. Notification ≠ Domain Truth.
6. Message ≠ Permission.
7. Conversation ≠ Permission.
8. Channel ≠ Sale.
9. Communication لا تملك Sale/Payment/Health/Finance truth لمجرد الإخطار.
10. Authorization decision من SPEC-0003.
11. Role Assignment ≠ Authorization.
12. Person alone لا يثبت Activity context.
13. Agent ≠ Domain Owner.
14. Delivery ≠ Domain completion.
15. Read ≠ Approval.
16. Offline ≠ Finality.
17. لا Notification Concept جديد.
18. لا Protocol/API/UI/Provider.
19. لا Concept أو Relationship جديد.

## 20. Acceptance Criteria
- AC-01 Conversation وMessage منفصلان.
- AC-02 Channel Context لا يتحول إلى Conversation تلقائياً.
- AC-03 Message يمكن أن تشير إلى Domain Reference دون نقل الملكية.
- AC-04 sender/context واضحان ضمن Activity عند الحاجة.
- AC-05 Authorization يبقى لدى SPEC-0003.
- AC-06 الإشعار لا يثبت Decision أو Domain Finality.
- AC-07 فشل/تأخر/تكرار Message لا يعيد كتابة Domain Truth.
- AC-08 لا Notification Concept مستقل.
- AC-09 Offline/Agent boundaries محفوظة.
- AC-10 REQ-0030/0031/0032 مغطاة وفق الملكية.
