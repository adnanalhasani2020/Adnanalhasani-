# SPEC-0016 — السندات والقسائم

## 1. الغرض والنطاق
تحدد هذه المواصفة السلوك الدلالي لمفهوم Instrument في سياق السندات والقسائم، وحدوده مع Sale وInvoice وPayment وSettlement، وكيفية تتبع الإصدار والاستخدام والانتهاء والإلغاء والأثر المرتبط بالعملية.
لا تنشئ Coupon أو Voucher أو Discount أو Promotion كـConcepts مستقلة؛ تستخدم Instrument كمفهوم Stage 5 الوحيد ضمن هذا النطاق.
لا تحدد قاعدة قانونية لنوع السند ولا آلية تقنية أو DB أو SQL أو API أو UI أو مزوداً.

## 4. المفاهيم المستخدمة
Instrument، Sale، Offering، Invoice، Payment، Settlement، Financial Transaction، Ledger Entry، Financial Account، Provenance، Audit Record، Authorization Grant، Device، Pending Operation.
لا Coupon/Voucher/Discount/Promotion Concept جديد.

## 5. Instrument
Instrument هو المفهوم العام لسند ذي معنى أو حق/قيمة قابلة للاستخدام ضمن سياق محدد.
قد يحمل دلالياً:
- issuer/holder أو beneficiary بحسب السياق.
- purpose أو نطاق الاستخدام.
- value/rights.
- issue date وvalidity.
- status.
- usage/redemption history.
- provenance.
هذه المواصفة لا تحسم التصنيف القانوني أو النوع النهائي للسند؛ DEC-0001 وDEC-0005 يبقيان DECIDED / RESOLVED.

**Instrument ≠ Invoice ≠ Payment ≠ Settlement.**

## 6. الإصدار
الإصدار يعني إنشاء/إقرار Instrument صالحاً للاستخدام وفق السياق المسموح.
الإصدار لا يعني:
- إنشاء Invoice.
- إتمام Payment.
- إتمام Settlement.
- إنشاء Financial Account.
- إنشاء Ledger Entry.
ولا يترتب عليه أثر مالي نهائي إلا إذا اعترف Owner Domain المالي بالأثر وفق قواعده.

## 7. الاستخدام والأثر على البيع/الدفع
يمكن استخدام Instrument أثناء Sale أو Payment أو في سياق مرتبط بهما.
الاستخدام يحدد دلالياً:
- أي Instrument استُخدم.
- في أي سياق/عملية.
- النتيجة: قُبل، رُفض، استُهلك، بقي قابلاً للاستخدام، أو تعذر تطبيقه عند انطباق المعنى.
استخدام Instrument لا يحول Instrument إلى Sale أو Invoice أو Payment أو Settlement.

إذا غيّر الاستخدام نتيجة Sale أو Payment، فالتغيير يبقى في المجال المالك لتلك الحقيقة:
- Sale/Invoice → Commerce.
- Payment/Settlement → Payments.
- Financial Transaction/Ledger Entry/Balance → Finance.
Instrument لا يملك هذه الحقائق.

## 8. دورة الحياة
يمكن أن يمر Instrument دلالياً عبر:
**issued → active → used / partially used → expired / cancelled**
بحسب السياق.
ليست كل الحالات إلزامية لكل Instrument.
- **issued:** أصبح السند صادراً وفق السياق.
- **active:** ما زال قابلاً للاستخدام.
- **used:** استُخدم كلياً أو تحقق شرط استخدامه.
- **partially used:** بقي جزء من الحق/القيمة عند انطباق المعنى.
- **expired:** انتهت صلاحيته.
- **cancelled:** أُلغي أو سُحب وفق القاعدة المطبقة.
الانتهاء أو الإلغاء لا يمحوان تاريخ الإصدار أو الاستخدام.

## 9. Failure / Exception boundaries
- Instrument غير صالح ≠ Invoice مرفوضة بالضرورة.
- رفض استخدام Instrument ≠ إلغاء Sale تلقائياً.
- انتهاء Instrument ≠ حذف تاريخ استخدامه.
- إلغاء Instrument ≠ حذف Payment أو Settlement السابقة.
- تكرار محاولة الاستخدام لا ينشئ Instrument جديداً تلقائياً.
- Pending Operation على Device لا تجعل Instrument أو أثره المالي نهائياً.
- لا تحسم المواصفة سياسة الاسترداد أو الأثر القانوني لنوع غير معتمد.

## 10. History / Provenance / Audit
Usage/Redemption history يوضح استعمال Instrument وتغير حالته.
Provenance يصف أصل Instrument أو عملية تغييره.
Audit Record يسجل الأفعال أو القرارات اللازمة للتدقيق.
**Provenance ≠ Audit Record ≠ Domain Truth.**
Correction أو cancellation لا يمحو التاريخ السابق.

## 11. Authorization / Privacy
استخدام Instrument أو الاطلاع على تفاصيله يخضع للسياق والسلطة عندما تكون البيانات أو العملية حساسة.
Role أو Channel أو Agent لا يمنح صلاحية مالية أو تجارية بذاته.
Agent يمكنه التعامل مع Instrument فقط ضمن Authorization القائمة ولا يوسّعها.
لا تضيف هذه المواصفة سياسة خصوصية أو تصنيفاً قانونياً جديداً.

## 12. Offline / Agent
**Offline ≠ Finality.**
Pending Operation لا تصبح Domain Truth لمجرد وجودها على Device.
استخدام Instrument offline قد يمثل محاولة/عملية معلقة، ولا يثبت وحده الأثر النهائي على Sale أو Payment أو Finance.
Agent لا يصبح مالك Instrument ولا مالك الأثر المالي الناتج.

## 19. الخلاصة
