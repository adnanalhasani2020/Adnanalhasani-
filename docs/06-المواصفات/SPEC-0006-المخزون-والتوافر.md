# SPEC-0006 — المخزون والتوافر

## 1. الغرض والنطاق
تحدد هذه المواصفة السلوك الدلالي لـInventory Position وAvailability وحدودهما مع Product وOffering وSale وDiscovery.
القاعدة المركزية:
**Offering ≠ Inventory Position ≠ Availability**.
لا تنشئ هذه المواصفة Stock أو Warehouse أو Price، ولا تحدد Availability Algorithm أو Inventory Algorithm أو Sync/Conflict Resolution algorithm أو API/UI/DB.

## 2. REQ Traceability والملكية
| REQ | Primary | Supporting | تغطية |
|---|---|---|---|
| REQ-DATA-0014 | SPEC-0005 | SPEC-0006 | فصل Offering عن Inventory Position |
| REQ-FUNC-0015 | SPEC-0006 | — | معنى وحالة Inventory Position |
| REQ-FUNC-0016 | SPEC-0014 | SPEC-0006 | فصل Availability عن Product/Offering |
لا تعيد المواصفة توزيع الملكية. Inventory يملك Inventory Position، وDiscovery يملك Availability كنتيجة اكتشاف؛ SPEC-0014 يملك سلوك Discovery الأساسي.

## 3. Dependencies
وفق جرد Stage 6:
- Domain Constraint: Inventory owns Inventory Position and Availability ضمن الحدود المحددة.
- SPEC-0014 consumes Inventory Position/Availability في سياق Discovery.
- External: DEC-0009 وDEC-0012.
لا توجد SPEC dependency جديدة في هذه المواصفة.

## 4. المفاهيم المستخدمة
Inventory Position، Availability، Product، Offering، Activity، Sale، Discovery، State Record، Provenance، Audit Record، Device، Pending Operation، Conflict.
لا تضيف هذه المواصفة أي Concept جديد.

## 5. Inventory Position
Inventory Position هي حقيقة حالة حيازة/كمية مخزون في سياق مكاني.
هي ليست Product ولا Offering ولا Availability ولا Sale.
يملك Inventory الحقيقة المتعلقة بالكمية/الحالة/الموقع ضمن الحدود المفاهيمية القائمة.

### 5.1 دورة الحياة
يمكن أن تمر دلالياً بحالات:
**unknown → available/reserved → depleted**
مع **adjusted** عند التصحيح، دون فرض taxonomy إضافية.
الحالة تصف Inventory Position ولا تنشئ Stock ككيان.

### 5.2 المعنى
وجود Inventory Position لا يعني أن Offering متاح للبيع الآن.
وجود كمية مسجلة لا يحسم وحده المكان أو الزمن أو شروط الاكتشاف.
Correction لا يمحو التاريخ السابق.

## 6. Offering ≠ Inventory Position
Offering يصف عرض Product/Service داخل Activity.
Inventory Position تصف حالة مخزون في سياق مكاني.
يمكن أن يوجد:
- Offering دون Inventory Position.
- Offering مع أكثر من Inventory Position.
- Inventory Position دون أن يكون العرض قابلاً للاكتشاف أو البيع في كل سياق.
لا تنتقل ملكية Inventory Position إلى Commerce بسبب ارتباطها بـOffering.

## 7. Availability
Availability هي نتيجة مشتقة زمانية/مكانية في سياق Discovery، وليست كمية مخزون ولا صفة ثابتة للProduct.
يمكن أن تتأثر بمعلومة Inventory، وبالزمن والمكان والسياق، لكن مصدر كل حقيقة يبقى لدى مالكها.

### 7.1 حالات Availability
الحالات المفاهيمية القائمة:
**computed → stale → invalid**
وقد تكون computed صالحة ضمن valid-at/freshness المحددين دلالياً.
لا تفرض هذه المواصفة معنى قانونياً أو تجارياً لكلمة "متاح".

## 8. Offering ≠ Availability
وجود Offering لا يثبت:
- التوفر الحالي.
- القرب المكاني.
- وجود كمية كافية.
- صلاحية العرض في كل زمان أو مكان.
كما أن وجود Inventory Position لا يجعل Availability ثابتة.

## 9. Inventory وDiscovery
Inventory يملك حقيقة Inventory Position.
Discovery يملك نتيجة Availability كما تظهر في سياق الاكتشاف.
يمكن لـDiscovery قراءة Inventory، ويمكن للتجارة قراءة Inventory، لكن القراءة لا تنقل Source of Truth.
ظهور Offering في Discovery لا يثبت Sale.

## 10. الزمن والمكان والـfreshness
Availability مرتبطة مفاهيمياً بـvalid-at وfreshness وبسياق المكان والزمن.
لا تحدد هذه المواصفة:
- تعريفاً نهائياً لـ"قريب".
- خوارزمية حساب التوفر.
- cache/index/search strategy.
هذه الحدود تتبع DEC-0009 ونطاق SPEC-0014.

## 11. التعارض بين Inventory وAvailability
عند اختلاف تمثيل Availability عن Inventory:
1. Inventory Position تبقى حقيقة Inventory.
2. Availability قد تصبح stale أو invalid أو تحتاج إعادة تقييم.
3. لا تنشئ المواصفة حقيقة ثالثة.
4. لا تحدد قاعدة حسم تقنية.
5. DEC-0012 أصبح DECIDED / RESOLVED ولا يتحول إلى قرار.

إذا وقع تعارض محلي بين تمثيلات Inventory نفسها، يبقى الحسم عند Owner Domain وفق القرار المفتوح؛ لا تفترض أولوية جهاز أو نسخة محلية.

## 12. العلاقة مع Sale
Commerce قد يستخدم Inventory information عند تقييم Sale، لكن:
**Inventory Truth ≠ Sale Truth**.
لا ينشئ وجود Inventory Position Sale تلقائياً.
ولا يضمن وجود Sale استمرار التوفر.
لا تملك هذه المواصفة lifecycle البيع؛ ذلك ضمن SPEC-0005.

## 13. الحالات والاستثناءات
- Inventory Position مجهولة: لا تُفسر كـavailable.
- Inventory Position depleted: لا تُفسر كـAvailability إيجابية.
- Availability stale: لا تُستخدم كحقيقة حالية غير مشروطة.
- Availability invalid: لا تُعامل كدليل على التوفر.
- تصحيح Inventory: يغير الحقيقة الحالية وفق قواعد Inventory ويحافظ على التاريخ.
- فشل تحديث محلي: لا يجعل Device مصدر الحقيقة.

## 14. History / Provenance / Audit
الحالة الحالية منفصلة عن التاريخ.
Provenance يصف مصدر/اشتقاق Inventory Position أو Availability عند الحاجة، ولا يصبح Inventory Truth.
Audit Record يسجل الفعل/التغيير لأغراض التدقيق، ولا يصبح Source of Truth.
Correction لا يساوي Delete History.

## 15. Privacy / Authorization
الوصول إلى معلومات المخزون أو التوفر يخضع للسلطة والسياق القائمين.
لا تمنح Inventory Position أو Availability صلاحية جديدة.
Authorization decision يظل لدى Authorization وفق SPEC-0003.
لا تستخدم هذه المواصفة Role Assignment كبديل عن Authorization.

## 16. Offline / Agent
**Offline ≠ Finality**.
Device وPending Operation وConflict ليست Source of Truth للمخزون.
Agent يمكنه قراءة أو اقتراح أو تنفيذ فعل مخول، لكنه لا يملك Inventory Truth ولا Availability Truth ولا ينشئ سلطة لنفسه.
عند وصول تحديث محلي متعارض، لا تحسم المواصفة التعارض بخوارزمية.

## 19. Acceptance Criteria
- AC-01 يمكن وجود Offering دون Inventory Position.
- AC-02 لا يستنتج وجود كمية من مجرد وجود Offering.
- AC-03 يمكن أن تكون Inventory Position موجودة بينما Availability stale/invalid.
- AC-04 Availability مرتبطة بالزمن والمكان والسياق.
- AC-05 Source of Truth للمخزون يبقى Inventory.
- AC-06 Source of Truth لنتيجة Availability يبقى Discovery.
- AC-07 التعارض لا ينقل الملكية إلى Commerce أو Device.
- AC-08 DEC-0009 وDEC-0012 يبقيان مفتوحين.
- AC-09 لا تنشئ المواصفة Stock/Warehouse/Price أو خوارزمية.
- AC-10 REQ-0014/0015/0016 موثقة مع Primary/Supporting كما في المصفوفة.

## 20. Traceability
REQ-DATA-0014: Primary SPEC-0005، Supporting SPEC-0006؛ هذه المواصفة تضبط حد Inventory فقط.
REQ-FUNC-0015: Primary SPEC-0006؛ تغطية الحالة والحيازة والسياق المكاني.
REQ-FUNC-0016: Primary SPEC-0014، Supporting SPEC-0006؛ هذه المواصفة توفر Inventory/Availability boundary ولا تملك Discovery behavior.

## 21. Open Decisions
- DEC-0009 DECIDED / RESOLVED: معنى "متاح قريباً" وما يرتبط به من حدود Discovery.
- DEC-0012 DECIDED / RESOLVED: مصدر/قاعدة الحسم عند اختلاف الحالات.
- Q-0009/Q-0021/Q-0018/Q-0019 تبقى ضمن نطاقها الأصلي.
لا تغلق هذه المواصفة أي DEC ولا تنشئ قراراً جديداً.

## 22. الحدود وما لا تحدده
لا تحدد DB أو SQL أو API أو UI أو Framework أو Provider أو Cloud.
لا تحدد Stock أو Warehouse أو Price.
لا تحدد خوارزمية Inventory أو Availability أو Sync أو Conflict Resolution.
لا تعيد تعريف Sale أو Payment أو Finance.
لا تبدأ SPEC-0014 ولا أي SPEC أخرى.

## 23. الخلاصة
**Inventory Position هي حقيقة المخزون؛ Availability هي نتيجة اكتشاف زمانية/مكانية؛ Offering هو العرض التجاري.**
الفصل بينها محفوظ، وDEC-0009 وDEC-0012 DECIDED / RESOLVEDان، ولا تنتقل الملكية إلى Commerce أو Discovery بسبب القراءة أو الارتباط.
