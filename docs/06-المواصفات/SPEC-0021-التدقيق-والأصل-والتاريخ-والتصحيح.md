# SPEC-0021 — التدقيق والأصل والتاريخ والتصحيح

## 1. الغرض والنطاق
تحدد هذه المواصفة السلوك الدلالي للتتبع والتدقيق والأصل والتاريخ والتصحيح عبر العمليات الحساسة، مع إبقاء الحقيقة الدومينية عند Owner Domain.
**Provenance ≠ Audit Record ≠ Domain History.**
**Correction ≠ Delete History.**
لا تنشئ Version Concept جديداً ولا تنقل Domain Truth إلى سجل التدقيق أو الأصل.

## 3. Dependencies
- Domain Constraint: Owner Domain retains Domain Truth.
- SPEC-0017: Agent Action وحدود السلطة.
- SPEC-0016: Instrument usage/history.
- External: DEC-0001.
لا تنشئ Version Concept أو Audit domain مستقل جديداً.

## 4. المفاهيم المستخدمة
Agent Action، Provenance، Audit Record، Domain History، Correction، Instrument، Sale، Payment، Settlement، Clinical Record، Financial Transaction، Ledger Entry، Authorization Grant، Device، Pending Operation، Conflict.
لا Version Concept جديد.

## 5. الفصل الأساسي
Provenance يصف أصل المعلومة أو الفعل ومساره ومصدره عند الحاجة.
Audit Record يسجل الفعل أو الوصول أو القرار أو التغيير المطلوب للتدقيق.
Domain History يمثل تاريخ الحقيقة التي يملكها Owner Domain.
**Provenance ≠ Audit Record ≠ Domain History.**
لا يصبح أي منها مصدراً بديلاً للحقيقة الدومينية.

## 6. Agent Action
**Agent Action ≠ Domain Truth.**
إذا غيّر Agent فعلاً مصرحاً به مجالاً ما، فإن Owner Domain يملك النتيجة؛ Agent Action وProvenance وAudit تسجل سياق الفعل دون امتلاك الحقيقة الناتجة.

## 7. التاريخ والتصحيح
Domain History ليست مجرد سجل تدقيق.
Correction يعني معالجة حقيقة أو حالة سابقة وفق معنى المجال مع الحفاظ على ما يلزم من التاريخ.
**Correction ≠ Delete History.**
لا تنشئ المواصفة Version Concept؛ تستخدم Domain History وCorrection والمفاهيم القائمة.

## 8. العمليات الحساسة
عند الحاجة يكون قابلاً للتتبع دلالياً: الفاعل، الفعل/الوصول، السياق أو الغرض، النتيجة، مصدر السلطة، والتغيير أو التصحيح اللاحق.
لا تفرض حقولاً تقنية أو schema.

## 9. حدود المجالات
استخدام Instrument يمكن تتبعه دون أن يصبح Sale/Invoice/Payment/Settlement.
الأثر المالي النهائي يبقى Finance؛ Sale/Invoice لدى Commerce؛ Payment/Settlement لدى Payments؛ والحقيقة السريرية لدى Health.
SPEC-0021 يسجل الأثر التدقيقي ولا ينتزع ملكية هذه الحقائق.

## 10. Failure / Exception
- Audit Record موجود ≠ الفعل نجح.
- Provenance موجود ≠ المعلومة صحيحة.
- Correction ≠ Delete History.
- Agent Action failed ≠ Domain Truth.
- Device/Pending Operation ≠ Domain History نهائية.
- Conflict record ≠ resolved Domain Truth.

## 11. Authorization / Privacy
التدقيق والتتبع لا يمنحان صلاحية جديدة.
الوصول للمعلومات الحساسة يخضع Authorization والسياق والغرض.
Audit Record وProvenance ليسا تصريحاً.

## 12. Offline / Agent
Offline لا يمنح Finality.
Pending Operation قد تحتاج إلى تتبع لكنها لا تصبح Domain History نهائية محلياً.
Agent Action offline لا تصبح Domain Truth.
