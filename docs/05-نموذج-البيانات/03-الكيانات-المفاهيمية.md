# الكيانات والمفاهيمية — النموذج التفصيلي

## النطاق
هذا نموذج مفاهيمي لا يحدد جداول أو مخطط قاعدة بيانات. المفهوم وحدة معنى مستقلة لها مالك وحالة وعلاقات وزمن وأصل.

**عدد المفاهيم الدومينية الأساسية: 47، إضافة إلى State Record كأداة نمذجة وصفية غير مستقلة.**

## Invariants العابرة للمجالات
1. Person لا يتكرر فقط لتغيير Activity أو Role.
2. Role وFamily Relationship لا يتحولان تلقائياً إلى Authorization.
3. Product وOffering وInventory وAvailability وSale مفاهيم مستقلة.
4. Obligation وDebt وLoan ليست مترادفات.
5. Invoice وPayment وSettlement وLedger Entry ليست مفهوماً واحداً.
6. Balance مشتق ولا يصبح مصدر حقيقة ثانياً.
7. Clinical Record لا يصبح Commercial Record.
8. Recommendation لا تساوي Approval ولا Execution.
9. Provenance لا يساوي Audit.
10. Offline لا يساوي Finality.
11. Device وReplica وPending Operation لا تملك Domain Truth.
12. التصحيح لا يمحو القدرة على تفسير التاريخ.

## ملاحظات خاصة
- Person → Access Account → Authenticator → Session، وبشكل مستقل Person → Financial Account.
- Person ↔ Membership ↔ Activity وMembership ↔ Role Assignment علاقات زمنية.
- Product → Offering → Sale، وOffering ↔ Inventory، وAvailability مشتق زماني/مكاني.
- Sale → Invoice/Obligation → Payment → Settlement → Ledger Entry → Balance، مع بقاء Invoice في Commerce كوثيقة، واعتراف Finance بالأثر المالي.
- Loan ↔ Parties → Obligations/Debt دون افتراض أنه Sale.
- Person → Patient Context → Encounter → Clinical Record → Result/Report/Prescription بالتوازي مع Service → Financial Reference.
- Family Relationship → Delegation → Authorization Grant → Agent Action، مع Approval عند الحاجة.
- Agent → Authority Policy لا يعني ملكية Domain.
- Device → Pending Operation → Submission → Domain Truth، والتعارض يذهب إلى Conflict/Resolution.


## تعميق دفعة 1 — Identity / Activities / Products

### Identity / Access

| المفهوم | المعنى | lifecycle | الزمن | الحقيقة/التغيير |
|---|---|---|---|---|
| Person | الشخص/الجهة التي تستمر هويتها عبر سياقات الوصول والنشاط | created → active/inactive → corrected | identity + recorded/correction | Identity |
| Identifier | معرف/مرجع مرتبط بالشخص وله صلاحية مستقلة | issued → active → replaced/expired/revoked | valid-from/to + recorded | Identity |
| Access Account | سياق وصول للنظام | created → active → suspended → restored/expired/revoked | activation/suspension/revocation | Access |
| Authenticator | وسيلة إثبات حيازة/سيطرة للمصادقة | enrolled → active → lost/revoked/expired → replaced | enrollment/revocation/replacement | Access |
| Session | سياق وصول مؤقت | started → active → terminated/expired | start/end/termination | Access |

Person الواحد قد يرتبط بأكثر من Access Account عندما توجد سياقات وصول مستقلة ذات معنى دلالي/إداري مستقل. الأصل عدم نقل Access Account بين الأشخاص؛ أي استثناء مستقبلي يحتاج واقعة إدارية/قانونية موثقة ولا يعيد تعريف الهوية.

Identity ≠ Authentication ≠ Authorization:
- Identity = من هو الشخص/الجهة.
- Authentication = إثبات الحيازة/السيطرة اللازمة لسياق الوصول.
- Authorization = ما يجوز فعله داخل سياق وغرض ونطاق.
- Identifier ليس Authenticator، وAuthenticator ليس Authorization Grant.

### أحداث وتصحيحات الهوية والوصول

- identity correction: تصحيح Person/Identifier مع حفظ التاريخ اللازم للفهم.
- identifier replacement: إنهاء صلاحية السابق وربط البديل دون محو التاريخ.
- access suspension: تغيير Access Account فقط.
- authenticator revocation: إبطال الوسيلة المتأثرة فقط.
- session termination: إنهاء Session دون تغيير Person أو Financial Account.
- فقد Authenticator لا يساوي فقد Device ولا يغير Identity.

Device لا يصبح Identity؛ الجهاز سياق تشغيل يحمل Sessions/Pending Operations ولا يعرّف الشخص.

### Activities / Memberships / Roles

Activity وOrganization حقائق مستقلة عن Person. Membership تثبت الارتباط بالنشاط، وRole Assignment مسؤولية محددة داخل سياق وفترة.

| المفهوم | lifecycle والزمن |
|---|---|
| Membership | proposed → active → suspended → ended/revoked؛ effective_from/effective_to |
| Role Assignment | assigned → active → suspended/revoked/expired؛ فترة فعالية مستقلة |
| Activity | established → active → suspended/closed |
| Organization | established → active → dissolved |

يمكن تداخل Role Assignments إذا كان ذلك مقصوداً دلالياً. إنهاء العضوية/الدور لا يمحو التاريخ.

Owner ≠ Manager ≠ Employee ≠ Customer. هذه أوصاف سياقية وليست هويات جديدة، ولا تنشئ Authorization أو Financial Account تلقائياً.

Role ≠ Permission ≠ Authorization؛ Role Assignment قد يدخل في تقييم الصلاحية لكنه لا ينشئ Authorization Grant بذاته.

### Products / Services / Offerings

Product تعريف عام يمكن أن يظهر في عدة Activities. Service معنى خدمة دوميني مستقل عندما تكون الخدمة نفسها موضوعاً للهوية/الحالة/الاستخدام. Offering عرض Product أو Service داخل Activity، ويمكن أن يختلف وصفه وشروطه وفترته دون نسخ Product/Service.

Offering lifecycle: draft → published → active → suspended/withdrawn → expired/retired. إيقاف Offering لا يحذف Product/Service ولا يعيد كتابة عروض سابقة.

### Inventory / Availability

Inventory Position تمثل حقيقة كمية/حالة مخزون في سياق مكاني/تشغيلي. لا نضيف Warehouse أو Location كمفهوم دوميني مستقل الآن؛ Location Context كافٍ.

on-hand وreserved معنيان مخزنيان مختلفان، وavailable قيمة مشتقة حالياً من on-hand وreserved والقيود ذات الصلة. adjustment تصحيح معترف به مع أثر تاريخي. لا نضيف Stock Ledger أو Quantity Event في هذه الدفعة.

Availability نتيجة مشتقة من Inventory/Offering/الوقت/الموقع/القواعد، ولها valid-at وfreshness عند الحاجة. قد تصبح stale دون أن تتغير Inventory Truth.

Inventory Truth ≠ Availability Result.
