# الأنشطة والأدوار والعضويات
Person ↔ Membership ↔ Activity/Organization ↔ Role Assignment.
العضوية علاقة؛ الدور مسؤولية داخل السياق؛ Employee ليس هو Person؛ Employee ليس Owner.
FHIR PractitionerRole يربط الشخص بالمنظمة والدور والموقع والخدمة والفترة، ويسمح بتعدد الأدوار والفترات؛ الدليل مفيد دون تبني FHIR حرفياً.
التوصية: تعدد الأنشطة والأدوار مع فترة وحالة ومصدر إثبات عند الحاجة. الدور وحده لا يصبح Authorization.
DEC-0008: Channel Context مستقل عن Sale/Payment.

## تعميق دفعة 1

### Person / Membership / Role / Authorization

- Person = الهوية.
- Membership = علاقة الشخص/السياق بالنشاط.
- Role Assignment = مسؤولية داخل السياق.
- Authorization = منحة صلاحية قابلة للتقييم.
- لا يُضاف مفهوم فاعل عام مستقل في هذه الدفعة؛ Person/Agent وسياق الفعل والعضوية/الدور يغطي الحاجة الحالية.

يمكن للشخص نفسه أن يكون Owner وManager وEmployee وCustomer في نشاط واحد أو أنشطة متعددة دون Person جديد أو Financial Account أو Authorization تلقائياً.

### Membership lifecycle

proposed → active → suspended → ended/revoked

effective_from/effective_to يصفان فترة المعنى. suspension يوقف الأثر الحالي دون محو التاريخ. تغيير العضوية لا يغير Person.

### Role Assignment lifecycle

assigned → active → suspended → revoked/expired

لكل إسناد فترة مستقلة. يمكن تداخل الأدوار إذا كان التداخل مقصوداً ومعبراً عنه زمنياً. إنهاء الدور لا يمحو الأدوار السابقة.

### Owner / Manager / Employee / Customer

هذه أوصاف سياقية لعلاقة أو دور، وليست أربع هويات. لا نستنتج منها Authorization؛ Authorization تحتاج منحة/قاعدة مستقلة.

Activity يملك حقيقة Membership وRole Assignment ضمن سياقه؛ Authorization يملك Authorization Grant. طلب التغيير ليس موافقة.
