# مصادر الحقيقة والبيانات المشتقة
Owner → Change Authority → Consumers → Derived Views.
Person → Identity؛ Access Account → Access؛ Financial Account → Finance؛ Obligation/Debt/Loan → Financial Relations؛ Invoice → Commerce؛ Payment/Settlement → Payments؛ Ledger/Balance → Finance؛ Inventory → Inventory؛ Availability → Discovery؛ Clinical Record → Health؛ Family Relationship → Family؛ Authorization → Authorization؛ Audit → Governance/Audit.
كل Derived View يحتاج source references واشتقاقاً وسياق freshness/validity عند الحاجة وإمكانية إعادة البناء أو الإبطال.
W3C PROV يدعم نمذجة الاشتقاق دون جعل المشتق حقيقة ثانية.

## تعميق دفعة 1 — Source of Truth

| الحقيقة | المالك | سلطة التغيير | المشتق |
|---|---|---|---|
| Person / Identifier | Identity | سلطة الهوية ضمن السياق | عروض الهوية |
| Access Account / Authenticator / Session | Access | سلطة الوصول | حالات العرض |
| Membership / Role Assignment | Activity | دور مخول داخل النشاط | ملخصات العضوية |
| Product / Offering / Sale | Commerce | دور تجاري مخول | عروض/قوائم مشتقة |
| Inventory Position | Inventory | دور مخزون مخول | Availability وملخصات |
| Availability | Discovery | نتيجة مشتقة من المصادر المسموح بها | نتائج اكتشاف أخرى |

قواعد الحسم:
- Person ليس مشتقاً من Access Account.
- Access Account ليس مصدراً لـAuthorization.
- Membership وRole Assignment ليستا Authorization.
- Offering لا يملك Inventory.
- Inventory Position لا تتحول إلى Availability.
- Availability لا تصبح Source of Truth ثانية عند قدمها أو انتشارها.
- إيقاف/تصحيح الحقيقة الأصلية لا يمحو المشتقات التاريخية دون قاعدة احتفاظ.

Availability يجب تفسيرها مع valid_at وfreshness عندما يؤثر الزمن. لا نختار cache/index/search implementation.

تعميق الدفعة 2 — Source of Truth المالي

| الحقيقة/المفهوم | المالك | ما الذي يقرأه الآخرون | ملاحظة |
|---|---|---|---|
| Financial Account | Finance | Finance Relations/Payments/authorized consumers | Access Account ليس مصدراً له |
| Obligation / Debt / Loan | Financial Relations | Commerce/Payments/Finance حسب السياق | Debt تصنيف لـObligation |
| Invoice state | Commerce | Finance/Payments | الأثر المالي لا يملكه Invoice نفسه |
| Financial Transaction / Payment / Settlement / Transfer | Payments | Finance/Commerce/authorized consumers | لا تُدمج دلالياً |
| Ledger Entry | Finance | Balance/Finance/authorized consumers | مصدر الحقيقة للأثر المالي المعترف به |
| Balance | مشتق | واجهات/تقارير/قراءات مالية | لا يصبح Truth ثانياً |

## قواعد الحسم

1. Financial Account لا يُستنتج من Access Account.
2. Invoice لا تصبح Ledger Truth بمجرد إصدارها.
3. Payment/Settlement لا يصبحان Ledger Truth إلا عندما يعترف Owner Domain بالأثر المالي وفق قواعده.
4. Balance يعاد اشتقاقه من مصدر الحقيقة المالي ولا يصحح Ledger بنفسه.
5. Pending Operation وConflict لا يملكان الحقيقة المالية.
6. النسخة التي وصلت أولاً ليست بالضرورة الحقيقة؛ الملكية الدلالية للمجال هي التي تحسم.
7. أي تصحيح مالي يجب أن يحافظ على القدرة على تفسير التاريخ.
