# مصادر الحقيقة والبيانات المشتقة
Owner → Change Authority → Consumers → Derived Views.
Person → Identity؛ Access Account → Access؛ Financial Account → Finance؛ Obligation/Debt/Loan → Financial Relations؛ Invoice → Commerce؛ Payment/Settlement → Payments؛ Ledger/Balance → Finance؛ Inventory → Inventory؛ Availability → Discovery؛ Clinical Record → Health؛ Family Relationship → Family؛ Authorization → Authorization؛ Audit → Governance/Audit.
كل Derived View يحتاج source references واشتقاقاً وسياق freshness/validity عند الحاجة وإمكانية إعادة البناء أو الإبطال.
W3C PROV يدعم نمذجة الاشتقاق دون جعل المشتق حقيقة ثانية.

## تعميق دفعة 1 — Source of Truth

| الحقيقة | المالك | سلطة التغيير | المشتق |
|---|---|---|---|
| Person / Identifier | Identity | سلطة الهوية ضمن السياق | عروض الهوية |
| Access Account / Authenticator / Session | Access | سلطة الوصول | حالات العرض |
| Membership / Role Assignment | Activity | دور مخول داخل النشاط | ملخصات العضوية |
| Product / Offering / Sale | Commerce | دور تجاري مخول | عروض/قوائم مشتقة |
| Inventory Position | Inventory | دور مخزون مخول | Availability وملخصات |
| Availability | Discovery | نتيجة مشتقة من المصادر المسموح بها | نتائج اكتشاف أخرى |

قواعد الحسم:
- Person ليس مشتقاً من Access Account.
- Access Account ليس مصدراً لـAuthorization.
- Membership وRole Assignment ليستا Authorization.
- Offering لا يملك Inventory.
- Inventory Position لا تتحول إلى Availability.
- Availability لا تصبح Source of Truth ثانية عند قدمها أو انتشارها.
- إيقاف/تصحيح الحقيقة الأصلية لا يمحو المشتقات التاريخية دون قاعدة احتفاظ.

Availability يجب تفسيرها مع valid_at وfreshness عندما يؤثر الزمن. لا نختار cache/index/search implementation.

تعميق الدفعة 2 — Source of Truth المالي

| الحقيقة/المفهوم | المالك | ما الذي يقرأه الآخرون | ملاحظة |
|---|---|---|---|
| Financial Account | Finance | Finance Relations/Payments/authorized consumers | Access Account ليس مصدراً له |
| Obligation / Debt / Loan | Financial Relations | Commerce/Payments/Finance حسب السياق | Debt تصنيف لـObligation |
| Invoice state | Commerce | Finance/Payments | الأثر المالي لا يملكه Invoice نفسه |
| Financial Transaction / Payment / Settlement / Transfer | Payments | Finance/Commerce/authorized consumers | لا تُدمج دلالياً |
| Ledger Entry | Finance | Balance/Finance/authorized consumers | مصدر الحقيقة للأثر المالي المعترف به |
| Balance | مشتق | واجهات/تقارير/قراءات مالية | لا يصبح Truth ثانياً |

## قواعد الحسم

1. Financial Account لا يُستنتج من Access Account.
2. Invoice لا تصبح Ledger Truth بمجرد إصدارها.
3. Payment/Settlement لا يصبحان Ledger Truth إلا عندما يعترف Owner Domain بالأثر المالي وفق قواعده.
4. Balance يعاد اشتقاقه من مصدر الحقيقة المالي ولا يصحح Ledger بنفسه.
5. Pending Operation وConflict لا يملكان الحقيقة المالية.
6. النسخة التي وصلت أولاً ليست بالضرورة الحقيقة؛ الملكية الدلالية للمجال هي التي تحسم.
7. أي تصحيح مالي يجب أن يحافظ على القدرة على تفسير التاريخ.


## تعميق الدفعة 3 — Source of Truth الصحي

| الحقيقة/المفهوم | المالك | سلطة التغيير | ما يقرأه الآخرون | ملاحظة |
|---|---|---|---|---|
| Patient Context | Health | سلطة صحية مخولة | Encounter/authorized consumers | ليس Identity ولا Access Account |
| Encounter | Health | سلطة رعاية مخولة | Clinical/Financial Reference/authorized consumers | لا يملك الأثر المالي |
| Clinical Record | Health | سلطة سريرية/توثيقية مخولة | Result/Report/Prescription/authorized consumers | الحقيقة السريرية؛ لا يتحول إلى Audit |
| Result / Report | Health | سلطة صحية مخولة | Clinical/authorized consumers | preliminary/final/amended لا تمحو التاريخ |
| Prescription | Health | سلطة سريرية مخولة وفق السياق | Patient/Encounter/authorized consumers | لا تساوي Recommendation أو Dispensing |
| Financial Reference | مالك العلاقة وفق سياق Health/Finance | سلطة المجال المختصة | Finance/Health authorized consumers | رابط فقط بين المجالين |
| Provenance | Governance/Domain context | بحسب المجال | تقييم الأصل/الثقة/التاريخ | لا يصبح Clinical Truth |
| Audit Record | Audit/Governance | سلطة التدقيق | أغراض الرقابة | لا يصبح Clinical History |

### قواعد الحسم الصحي

1. Person لا يُستنتج منه Patient Context كهوية جديدة؛ السياق الصحي يملكه Health.
2. Access Account لا يملك Patient Context.
3. Family Relationship لا تمنح وصولاً صحياً تلقائياً.
4. Clinical Record هو الحقيقة السريرية، وليس Provenance أو Audit.
5. Result/Report وPrescription حقائق صحية مستقلة، لكنهما لا ينقلان الملكية إلى Finance.
6. Recommendation وAgent Action لا تصبحان Clinical Truth تلقائياً.
7. Financial Reference لا يجعل Health مالكاً لـInvoice أو Ledger.
8. Pending Operation وConflict لا يملكان Final Clinical Truth.
9. التصحيح الصحي يحافظ على التاريخ، ولا يستبدل provenance أو audit.
10. Balance والبيانات المالية المشتقة تبقى خارج Health Truth.

## تعميق الدفعة 4 — Source of Truth

| الحقيقة/المفهوم | المالك | سلطة التغيير | ما يقرأه الآخرون | قاعدة الحسم |
|---|---|---|---|---|
| Family Relationship | Family/context owner | سلطة إثبات العلاقة في السياق | Authorization/Health/Activity حسب الحاجة | لا تمنح وصولاً تلقائياً |
| Delegation | Authorization | صاحب سلطة التفويض | Authorization evaluation | ليست Permission عامة |
| Authorization Grant | Authorization | Grantor/authority المخولة | Decision/Action consumers | لا تملك Domain Truth |
| Conversation | Communication | صاحب سياق التواصل | Participants/authorized consumers | ليست Clinical/Financial Truth |
| Message | Communication | المرسل/جهة التواصل المخولة وفق السياق | Participants/authorized consumers | لا تصبح Domain Record لمجرد محتواها |
| Agent | Governance/owning context | سلطة إدارة الوكيل | Policy/Action consumers | لا يملك الحقيقة الدومينية |
| Authority Policy | Authorization/Governance | صاحب السياسة المخول | Agent Action/Approval evaluation | ليست تنفيذ صلاحيات تقني |
| Agent Action | Domain + Governance context | وفق سياق الفعل والتدقيق | Domain owner/Audit/authorized consumers | ليس Source of Truth بحد ذاته |
| Approval | Governance | جهة القرار المخولة | Agent Action/Domain consumers | قرار محدد لا ملكية حقيقة |

### قواعد الحسم

1. Family Relationship لا تصبح Authorization بالاستنتاج.
2. Delegation لا تصبح Domain Truth في Health/Finance/Activity.
3. Authorization Grant لا تصبح Permission تقنية عامة.
4. Conversation/Message ليستا Clinical Record أو Invoice أو Payment أو Ledger Entry.
5. Agent Action لا يثبت وحده النتيجة النهائية في Health/Finance/Activity.
6. Approval لا يصحح أو يملك Domain Truth؛ هو قرار ضمن سياق فعل.
7. Provenance يشرح الأصل/الاشتقاق، وAudit Record يشرح ما يجب تدقيقه، وكلاهما منفصل عن الحقيقة الدومينية.
