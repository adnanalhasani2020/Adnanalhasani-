# الصحة والسجل السريري والخدمات الصحية

## الحالة
**تعميق مفاهيمي — Stage 5 / Batch 3.**

هذا الملف يحدد المعنى الصحي، مالك الحقيقة، سلطة التغيير، lifecycle، الزمن، التاريخ، provenance، audit والحدود مع المجالات الأخرى، ولا يحدد تمثيلاً تقنياً.

## 1. Patient Context

Patient Context هو سياق الشخص كمستفيد صحي، وليس هوية جديدة.

- Person هو الهوية.
- Patient Context هو سياق الرعاية.
- Health يملك الحقيقة.
- Access Account مستقل عنه.
- Family Relationship لا تمنح وصولاً تلقائياً.
- Delegation/Authorization تحدد الوصول أو الفعل ضمن النطاق.
- يمكن تعدد Patient Context فقط عند وجود سياقات مستقلة ذات معنى، لا لمجرد تعدد الزيارات أو الجهات.
- إنهاء السياق لا يمحو التاريخ الصحي.

## 2. Encounter

Encounter هو تفاعل رعاية محدد.

- يرتبط بـPatient Context.
- قد يرتبط بـService وبـActivity/Organization الصحية.
- قد يحتوي عدة Clinical Records.
- قد يرتبط بعدة Results/Reports وPrescriptions.
- قد ينتج Financial Reference دون امتلاك الأثر المالي.
- planned وin-progress وcompleted وcancelled حالات دلالية محتملة؛ interrupted لا تستخدم إلا إذا كان لها معنى مستقل.

Encounter لا يساوي Invoice أو Payment أو Financial Account.

## 3. Clinical Record

Clinical Record هو معلومة سريرية موثقة، وليس صندوقاً عاماً لكل بيانات المريض.

- Health هو مالك الحقيقة.
- يمكن أن تكون المعلومة مرتبطة بـEncounter أو Patient Context.
- draft وrecorded وamended وcorrected وinvalidated تستخدم فقط عندما تحمل معنى مستقلاً.
- التصحيح لا يمحو التاريخ.
- Current Clinical State لا يلغي Clinical History.
- لا نضيف Diagnosis/Allergy/Lab Test/Imaging Study/Medication ككيانات مستقلة الآن.

## 4. Result / Report

Result/Report هو نتيجة أو تقرير صحي ذو معنى دوميني، وليس مجرد ملف.

- يرتبط بـPatient Context عند كون الشخص موضوعه.
- قد يرتبط بـEncounter.
- قد يرتبط بـClinical Record.
- preliminary وfinal تميزان مراحل النتيجة عندما تكون ذات معنى.
- amended وcorrected تحفظان قابلية فهم التاريخ.
- يجب فصل effective/performed time عن issued/amended time.

## 5. Prescription

Prescription هو طلب/توجيه علاجي معترف به في السياق السريري.

Prescription ≠ Clinical Recommendation  
Agent Recommendation ≠ Prescription  
Prescription ≠ Medication Dispensing

قد ترتبط الوصفة بـPatient Context وEncounter وClinical Record، وبـAgent أو Approval فقط عندما توجد Authority Policy/Authorization مناسبة.

Agent لا يملك Clinical Truth.

الحالات الممكنة: draft، issued، active، amended، cancelled، expired، fulfilled بحسب السياق، وليس بالضرورة كلها لكل وصفة.

## 6. AI / Agent boundary

المسار المفاهيمي:

Clinical Information → Recommendation → Approval عند الحاجة → Agent Action / Human Action

- Recommendation ليست Clinical Decision.
- Agent Recommendation ليست Prescription.
- Agent Action لا تصبح Clinical Truth تلقائياً.
- Agent لا يملك سلطة طبية عامة.
- Authority Policy وAuthorization وApproval تحدد الحدود بحسب السياق.

WHO يؤكد في إرشاداته أن AI الصحي يحتاج حوكمة ومساءلة وحماية للاستقلال البشري، وأن القرارات الطبية ينبغي ألا تنتقل تلقائياً إلى الآلة. هذا دليل مفاهيمي وليس قراراً قانونياً للمشروع.

## 7. Health ↔ Finance

المسار الممكن:

Patient Context → Encounter → Service → Financial Reference → Invoice / Obligation / Payment

لكنه اختياري:
- الخدمة المجانية قد لا يكون لها أثر مالي.
- الخدمة المدفوعة قد تنتج Financial Reference.
- الالتزام والدفع والتسوية والدفتر تبقى في المجال المالي.
- Clinical Record وPrescription وEncounter لا تصبح Finance Truth.
- Financial Reference رابط بين المجالين فقط.

## 8. Family / Delegation / Children

Family Relationship لا تعني تلقائياً ملكية أو وصولاً إلى بيانات الطفل.

Delegation وAuthorization يمكن أن تحددا scope وaction وtarget وvalidity.

ولا يحسم هذا النموذج القانون المحلي للولاية أو الوصاية.

## 9. Privacy / Sensitivity

الصحة شديدة الحساسية.

يفصل النموذج بين:
- Data Classification.
- Purpose.
- Authorization.
- Audit.
- Retention.
- Legal Requirement.

هذه مفاهيم حوكمة؛ لا تتحول في هذه المرحلة إلى تصميم تشفير أو نظام صلاحيات تقني.

## 10. Provenance / Audit / Clinical Truth

Clinical Record/Result/Prescription = الحقيقة الصحية.

Provenance = من أين جاءت المعلومة ومن أنشأها/عدلها وما مصدرها أو اشتقاقها.

Audit Record = الفعل/الوصول/التغيير الذي يحتاج تسجيلاً رقابياً.

Provenance ≠ Audit ≠ Clinical Record.

هذا الفصل متسق مع HL7 FHIR، الذي يميز Provenance كسجل لسياق إنشاء/تعديل المعلومات، وAuditEvent كسجل لأحداث الاستخدام والتدقيق. هذا استخدام للدليل المعياري على المستوى المفاهيمي فقط.

## 11. الزمن

يجب أن يستطيع النموذج التفريق بين:
- clinical/effective time.
- encounter time.
- performed/result time.
- issued time.
- recorded time.
- amendment/correction time.
- cancellation/expiry time.

لا يعني تسجيل نسخة أحدث محو النسخة السابقة من التاريخ.

## 12. Offline

Pending Operation قد تمثل عملية صحية محلية، لكنها لا تصبح Final Clinical Truth لمجرد وجودها على Device.

Conflict لا ينشئ Clinical Truth ثانية. Owner Domain الصحي هو الذي يحسم الحقيقة وفق قواعد المجال.

لا توجد خوارزمية Sync/CRDT في هذا النموذج.
