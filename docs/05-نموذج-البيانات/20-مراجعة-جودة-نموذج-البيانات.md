# مراجعة جودة نموذج البيانات — تعميق

## الحكم
تم تحويل الجولة السابقة من قائمة مفاهيم + تتبع 59/59 إلى نموذج مفاهيمي قابل للمراجعة: قاموس 47 مفهوماً دومينياً + State Record كـModeling Construct، مصفوفة 57 علاقة رئيسية، cardinality مفاهيمية، lifecycle، temporal semantics، ownership، source/derived، provenance، invariants، واختبارات سيناريو.

| الفحص | النتيجة |
|---|---|
| Duplicate Concepts | لا تكرار دلالي جوهري؛ تم الفصل حيث تختلف الحقيقة أو دورة الحياة |
| Multiple Source of Truth | لا مصدران للحقيقة في المفاهيم الحساسة؛ المشتقات معلّمة |
| Hidden Many-to-Many | تمت معالجتها عبر Membership وOffering وParties وFamily Relationship وAuthorization وParticipants |
| Ambiguous Ownership | تم تعيين مالك مفاهيمي؛ بقيت حدود السياسات القانونية مفتوحة |
| Missing Lifecycle | مغطى للمفاهيم الأساسية |
| Missing Temporal Meaning | مغطى حيث يغيّر الزمن المعنى |
| State/Event mixing | مفصول |
| Provenance/Audit mixing | مفصول |
| Role/Family → Authorization | ممنوع كمساواة ضمنية |
| Financial merging | Account/Obligation/Debt/Loan/Invoice/Transaction/Payment/Settlement/Transfer/Ledger/Balance منفصلة |
| Clinical/Commercial mixing | منفصلان مع Financial Reference سياقي |
| Offline/Finality | منفصلان |
| Technical leakage | لا SQL/DB/API/ORM/Framework/Provider/خوارزمية مزامنة |
| Traceability | 59/59 بتعيين محدد |

## عدد المفاهيم
**47 مفهوماً دومينياً + State Record كـModeling Construct أساسياً.**

## عدد العلاقات
**57 علاقة رئيسية** في مصفوفة العلاقات، مع علاقات فرعية دلالية داخل بعض السياقات.

## مفاهيم فُصلت عمداً
1. Person / Access Account / Authenticator / Session.
2. Activity / Organization / Membership / Role Assignment.
3. Product / Offering / Inventory / Availability / Sale.
4. Financial Account / Ledger Entry / Balance.
5. Obligation / Debt / Loan.
6. Invoice / Financial Transaction / Payment / Settlement / Transfer.
7. Patient Context / Encounter / Clinical Record / Result / Prescription / Financial Reference.
8. Family Relationship / Delegation / Authorization Grant.
9. Agent / Authority Policy / Agent Action / Approval.
10. Provenance / Audit Record.
11. Device / Pending Operation / Conflict.

سبب الفصل في جميعها هو اختلاف المعنى أو المالك أو دورة الحياة أو الزمن أو مستوى الثقة في الحقيقة.

## مصادر الحقيقة
- Identity: Person وIdentifier.
- Access: Access Account وAuthenticator وSession.
- Activity: Activity وMembership وRole Assignment.
- Commerce: Product وOffering وSale وInvoice في حدودها التجارية.
- Inventory: Inventory Position.
- Discovery: Availability كمشتق.
- Financial Relations: Obligation وDebt وLoan.
- Payments: Financial Transaction وPayment وSettlement وTransfer.
- Finance: Financial Account وLedger Entry؛ Balance مشتق.
- Health: Patient Context وEncounter وClinical Record وResult/Report وPrescription.
- Family: Family Relationship.
- Authorization: Delegation وAuthorization Grant وAuthority Policy.
- Communication: Conversation وMessage.
- Instrument: Instrument ودورة استعماله.
- Governance: Approval وProvenance وAudit.
- Local/Device: Device وPending Operation وConflict ضمن حدودها التشغيلية؛ لا تملك Domain Truth.

## أهم invariants
1. Person ≠ Access Account ≠ Financial Account.
2. Role/Family ≠ Authorization.
3. Product ≠ Offering ≠ Inventory ≠ Availability ≠ Sale.
4. Obligation ≠ Debt ≠ Loan.
5. Invoice ≠ Payment ≠ Settlement ≠ Ledger.
6. Balance مشتق.
7. Clinical Record ≠ Financial Record.
8. Recommendation ≠ Approval ≠ Execution.
9. Provenance ≠ Audit.
10. Offline ≠ Finality.
11. Device/Replica/Pending ≠ Domain Truth.
12. Correction لا يمحو التاريخ.

## نتيجة اختبار السيناريوهات
**13/13 سيناريوهات تمر مفاهيمياً:**
1. شخص واحد يعمل في عدة أنشطة.
2. شخص واحد عميل وموظف ومدير.
3. شراء منتج من نشاط.
4. بيع آجل/دين.
5. دفع ثم تسوية.
6. قرض بين شخصين.
7. خدمة صحية لها جانب سريري ومالي.
8. طفل مع ولي/مفوّض.
9. وكيل ينفذ بعد موافقة.
10. عملية مالية Offline.
11. جهازان يعدلان نفس الحقيقة.
12. تعديل/تصحيح سجل تاريخي.
13. استعادة بعد فقد الجهاز.

المرور هنا يعني أن المفاهيم والعلاقات قادرة على تمثيل السيناريو، وليس أن السياسة أو القانون أو التنفيذ قد حُسم.

## القرارات القابلة للتوصية
DEC-0002، DEC-0003، DEC-0004، DEC-0005، DEC-0006، DEC-0007، DEC-0008، DEC-0009، DEC-0010، DEC-0011، DEC-0012، DEC-0013 أصبحت لها توصية بنيوية واضحة.

## قرارات تحتاج صاحب المشروع
DEC-0001، ومعه الاختيارات القانونية/المحلية التابعة له: Primary Account إن أُبقي، الدور القانوني للنظام المالي، سياسة الأسرة والوصاية، أنواع السندات/القسائم، حدود الوكيل، القنوات، تعريف القرب، أولوية القطاعات، offline المالي، recovery والتعارضات الخاصة.

## أهم المخاطر المتبقية
- تحويل المفاهيم إلى تمثيل تقني مبكراً.
- قواعد قانونية عالمية قبل تحديد الولاية.
- استنتاج Authorization من Role أو Family.
- جعل Balance أو Availability أو Replica مصدراً ثانياً.
- الخلط بين التصحيح والحذف.
- افتراض finality في Offline.
- توسع Agent Authority دون Policy/Approval.
- خلط Provenance وAudit بسبب تشابه initiator/time.
- استعمال «Account» أو «Relationship» بمعانٍ متعددة.

## نتيجة الجولة
**مقبول كمراجعة تعميق مفاهيمي، غير مقبول كإغلاق مرحلة.**

لا يوجد ACH، ولا تغيير لبوابة المراحل، ولا فتح مرحلة لاحقة، ولا مواصفة تقنية.

### مفاهيم لم تُضف

مفهوم فاعل عام، Product Variant، Unit/Measure، Price/Price Rule، Warehouse/Location لم تثبت حالياً كحقائق مستقلة لها معنى ومالك ودورة حياة لا يمكن تمثيلها بالمفاهيم الحالية. لا تُضاف لمجرد شيوعها في الأنظمة التجارية.

### مخاطر أُغلقت

1. Person/Access Account confusion.
2. Identifier/Authenticator confusion.
3. Role/Authorization inference.
4. فقد التاريخ عند انتهاء Membership/Role/Offering.
5. Product/Offering duplication.
6. Inventory/Availability confusion.
7. اعتبار Available حقيقة مستقلة.
8. اعتبار «متاح قريباً» خاصية Product.
9. إدخال مفاهيم غير لازمة.
10. تسرب search/cache/index إلى النموذج.

### مخاطر باقية

- القواعد القانونية/المحلية للهوية والأهلية والأسرة.
- حدود Authorization النهائية.
- احتمال الحاجة الدومينية المستقبلية إلى Location/Unit/Variant/Price Rule.
- سياسة التعارض النهائية المرتبطة بـDEC-0012.
- تفاصيل التنفيذ خارج نطاق Stage 5 الحالية.
